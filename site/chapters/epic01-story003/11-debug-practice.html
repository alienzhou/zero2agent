Agent Debug 方法论
调试实践：先看日志，再改代码
我自己用 Agent 修 bug 时，遇到困难问题，会让 Agent「先看日志、再修代码」。
除了确实能修一些疑难杂症外，这种方式修的问题一般会更精准。相信大家都遇到过 Agent 用临时方案修，把代码搞得很难维护。
按层选工具
分层上，我的习惯是先看预埋日志能不能兜住；兜不住再通过动态埋点，然后复现去修。那种本地特别特别妖的，也可以考虑开 CDP，不过一般动态日志成功率就很高了。
线上 vs 本地
线上：没有 inspect，只能靠开发阶段把预埋日志下扎实

本地：理论上五层都能走，按问题复杂度选工具
为什么要关注
把这些方法练熟，自己用 Agent 写代码会省很多时间。未来 Agent 自己的调试能力也会越来越重要。毕竟都接不住 bug 的 Agent，实在是“管杀不管埋”。
