Zero2Agent • 工具设计 03
设计 Agent 工具，
应该先想什么？
设计工作区工具时，我有一个习惯的概念判断：“对人友好的工具，对 Agent 也会友好”。如果一个工具连人类开发者拿着文档都很难理解它能做什么、不能做什么，Agent 拿到参数定义时也很难稳定用对。
1. 到底该不该做？
工具不是越多越好。新增之前，先拿三个标准拷问：现有能力的覆盖度够不够？它能否带来效果提升？它是否有成本优势（Token 消耗和执行耗时）？如果只是“能做”，那往往并不值得做。
2. 定义工具边界
确定要做后，必须明确工具边界，工具间最好能正交。以本期的 grep_search 为例：它只负责定位候选位置，绝对不负责直接生成答案，也不替代 read_file 的精读。边界一旦模糊，Agent 在复杂任务中就容易发生严重的工具混用。
不断添加工具/技能并不困难，难的是保持克制。
3. 克制的参数设计
不要把底层库（如 ripgrep）支持的所有参数全盘托出。判断标准很简单：不传这个参数，Agent 会犯致命错误吗？这部分复杂度能不能由其他方式消化？只有过滤无关变量，模型才能把有限的推理能力聚焦在“搜索什么内容”上。
4. 迭代与优化
工具做出来并不代表设计结束了。上线后还要继续看它是否真的好用。这本身也是个很复杂的话题，这里就先不扩展。Anthropic 去年有篇文章里提到他们如何做一个工具的，包括「用评测而不是感觉来判断工具是否变好」/「让 Agent 帮你分析评测结果」/「不只看最终正确率」
