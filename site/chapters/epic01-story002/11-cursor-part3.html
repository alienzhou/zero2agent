Cursor Grep 优化拆解 (三)：
为了零幻觉的绝对本地化
这套极其优越的索引数据，存在云端并不好。语义索引（Codebase RAG）放在服务端还算是 OK 的，代码稍微改动，在多维空间中的位移并不大，但仍然可能需要本地校准。
消除自我检索的幻觉
但正则搜索必须保持良好的新鲜度。按目前来看，Agent 搜索很频繁，并且对于 Grep 的理解就是“精准”搜索，如果网络往返产生几百毫秒的延迟同步差，就会很容易导致它搜不到自己写的东西，进而累计产生一些严重的幻觉。所以 Cursor 目前选择使用本地内存来存储索引信息。
使用本地内存来存储
mmap 内存映射
为了不吃爆本地编辑器的内存，Cursor 将索引分成两个文件落盘。一个存储连续的 Posting list，另一个极度紧凑的哈希表记录偏移量。

在编辑器进程中，只对这张寻址表执行 mmap。查询时直接二分查找拿到偏移，再精准从磁盘对应扇区抽回数据。配合监听本地 Git 状态做增量合并，实现了 Chromium 级别大仓中近乎瞬时且无感知占用的体验。
