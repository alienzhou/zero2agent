Sparse N-grams
长分词看起来不是一个好的解决方案，需要找了好办法。ClickHouse 和 GitHub 新版 Code Search 给出了一个可能的解法：稀疏 N-grams (Sparse N-grams)。
变长且离散的切片
它不再机械地每 3 个字符切一刀。算法会为文档中的每一对字符分配一个确定性的“权重”。只有当子串两端的权重大于内部包含的所有权重时，它才会被提取为一个 token。这意味着提取出的片段长度是随机变长的。

用算力换取极致过滤
建索引时付出了极高的算力提取特征，但在查询时，算法根本不需要全量匹配。因为权重是基于真实开源代码的频率表生成的（极其罕见的字符对权重最高），查询引擎只需要抽出搜索词中最冷门、区分度最高的边界 token 去查倒排索引。
只需极少的几次索引探测，就能将候选文件范围从几万个精准坍缩到个位数。剩下的，再交给传统的正则引擎在内存中做验证。
