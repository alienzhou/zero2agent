# E05-S002：按需加载要覆盖整条执行链

Skills 的核心不是读一个 SKILL.md，而是让目录、正文、资源在正确时刻进入真实请求。首个请求只给摘要，模型选择后才加正文，需要报告结构时才读取引用；工具回执只保留加载元信息，避免把正文永久复制进历史。

标准核对固定到官方源码：YAML 头部和字段约束采用开放格式，默认发现目录、容量、审批和刷新属于本产品策略。allowed-tools 为实验声明，不是宿主许可；compatibility 是说明文本，不是依赖安装器。仓库原 CDP 示例缺少合规头部和匹配目录，随实现修正。

整批 load_skill 与写操作必须先停下来。即使宿主已读取正文，提出写操作的那次模型请求还没见过它，不能先写后补规则。单独加载后再请求，当前技能版本变化时有界重新规划；审批或批中变化保留前面的真实效果并停止剩余调用。新增资源工具沿用原预算、权限和结果来源协议。

完整回归发现普通会话复用会多出空 Skills 覆盖层，使既有请求发生变化。独立审阅又复现审批时文件头部被换大，以及恢复时当前 --skill 选择被旧快照抹掉。这些都是实际兼容/边界问题，需要修实现并补回归，不能只修改旧测试期待。原失败日志与复现目录保留到外部归档。

课程按必要教学步骤安排 11 页（含封面），展示层次、选择、批次时序、路径边界、脚本授权与恢复。完整容量和故障表放进 Spec。浏览器自动几何检查之后仍检查实际图像：初版 YAML 结束线贴底、资源边界箭头穿字，修正后重新验 PC/H5。所有截图、请求、PTY 和源副本留在忽略目录与独立归档，Git 仅放复现脚本和精简索引。

真实服务首轮 v1 正常例完成源码、测试和真实进程，但把参考 JSON 中 evidence/report/rules 的说明外壳也写进了报告。完成校验发现缺字段与额外字段；模型修复时仍保留说明，重复写报告并耗尽 8 请求。该例保持失败，不通过增加预算或取消“每个目标只改一次”取得通过。拒绝例通过，当前策略没有被技能扩大。

独立审阅确认教材样例有歧义：文件叫 report-format.json，却把报告模板与说明包成另一份完整 JSON。修订独立冻结 fixtureVersion=2，只让参考文件直接给出三字段可填值模板，并额外检查最终摘要不是未替换占位符；原任务文字、技能步骤、模型、预算和文件效果门槛保持。v1 记录与源码完整保留，v2 是改变参考输入后的新验证，不宣称同输入改进或抹掉原失败。

完整 E2E 还发现帮助页测试把 /logs 必须显示在 42×18 小屏末屏当成了契约。新增 /skills 说明后，该行位于上方；实际焦点和输入未异常。修订测试使用既有 PgUp 滚动核对帮助内容，保留原时限与产品布局，完整失败终端另存。

最终真实服务与工程结果见 [验收记录](../specs/E05-extensibility/S002-skills/details/03-verification-checklist.md)。AI 交叉审阅不替代用户 review，本站未部署。

v2 正常任务严格通过，额外负例却在模型层提前安全拒绝，未触达宿主；原检查保持失败。独立核对生产字节、规范化后的负例请求、权限、恶意技能和脚本，确认负例未变化；唯一改变的正常参考文件也未被其读取。因此复用最早严格通过的 v1 宿主拒绝证据，配合 v2 正常通过覆盖两个能力门槛。两批仍各为 1/2，不改称同批 2/2、稳定复现或泛化成功，没有继续调用模型凑成绩。
