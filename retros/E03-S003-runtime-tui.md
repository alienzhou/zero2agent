# E03-S003：运行状态与 TUI 复盘

[课程](../specs/E03-product-foundations/S003-runtime-tui/README.md) | [验收](../specs/E03-product-foundations/S003-runtime-tui/details/03-verification-checklist.md)

## 从日志打印到可连续操作

最初范围围绕事件、审批和取消。用户指出旧 CLI 比较简陋，希望有良好的实际交互，因此交付标准补充了多行粘贴、命令补全、运行草稿、输入历史、工具详情、窄屏和视觉层级。仅把 stdout 包进全屏区域还不够；每个焦点下能做什么、输入能否保留，都需要独立验收。

## 有效的实现顺序

先固定 RuntimeEvent 与 cancelTurn 契约，再并行实现 Core 和 TUI。这样界面不必根据一段文字猜测工具是否执行，Core 也不依赖终端组件。保留 plain 通路，使旧课程仍能按原来的逐行交互跟练。

调研区分官方文档、固定源码和隔离的真实 PTY 观察。Codex 与 OpenCode 的本地编辑器观察没有发送模型任务；取消、审批与人工终端的保证仍以本项目实际验证为依据，不能从竞品截图推导。

## 自动化和视觉检查发现不同问题

Core 测试验证了流、计数和摘要请求取消，批量工具配对及非协作工具真实收尾。生产 CLI 接本地 SSE，再放入真实 PTY，能稳定制造需要人工输入的场景。真实模型补充验证了读取、拒绝/批准及取消前台命令，而不承担所有边界覆盖。

终端画面由实际 PTY 字节在 xterm.js 中重放，并保留原始输出和截图。第一次视觉检查发现拒绝理由重复打印、完成卡仍残留“需要审批”、展开 JSON 缺少连续边线，以及窄屏帮助被截掉。这些问题不会让工具测试失败，却会影响使用者理解状态。

## 独立审查补上的边界

审查重点放在状态身份与输入所有权：跨轮重复 toolCallId 必须连同 turnId 识别；旧 turn-start 不能覆盖新状态；人工 PTY 接管期间可能消费 bracketed paste 的结束标记，返回时需要重置输入模式；长 reason 也必须进入显示预算。

这些发现与最终修复验证记录在[源码复核](../.vibecoding/2026-10-07/e03-s003-runtime-tui/review.md)。测试绿灯不能替代需求逐项核对，也不能冒充用户人工审查。

## 旧交互需要逐项迁移

用户补充要求保留既有交互后，我们从旧 CLI 源码逐项检查 `/new`、`/compact`、人工终端、权限模式、前后台命令和退出清理，也补齐 readline 常用剪切与恢复键。超长输入审计进一步发现静默忽略问题：最终用有界的粘贴缓冲，在结束时整体接受或拒绝，超限明确提示并保留原草稿和光标。

真实模型验收也暴露过“文字声称执行、实际上没有调用工具”的情况。文件断言正确捕获了它；保留失败证据、把提示改为要求真实调用后复验，不能把模型自述当作完成证据。长期规则已进入 AGENTS.md，具体快捷键、容量与未迁移的高级 readline 行为则保留在使用文档和兼容矩阵。

## 下一次继续保持的边界

取消停止后续调度并收尾当前工作，已发生的文件写入仍保留。自定义工具忽略 signal 时继续显示取消中并等待；强制终止需要更强的运行隔离。会话落盘、持久日志和文件回滚仍按 S004、S005、S006 分开推进。

课程也直接在 zero2agent 内维护：规格、编辑源、在线 HTML、来源和审阅证据放在同一个仓库，避免旧素材仓库成为第二份事实源。后续章节应从验收矩阵开始，最终按矩阵核查源码、真实行为和教学产物。
