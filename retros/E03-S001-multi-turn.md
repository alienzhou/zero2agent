## 暴露的问题与修正

1. 第一版 E2E 已输出“再见”，但测试仍握着输入管道，三项用例各自超时。测试端在最后一行后关闭输入，随后的契约测试通过。
2. 展示回调的参数与工具输入原来共用引用，异步回调还可能返回 rejected Promise。输入深拷贝、拒绝捕获和提交快照隔离使展示不再改变执行事实。
3. 独立审查发现 `String(error)` 也可能抛错：例如 `Object.create(null)` 或抛错的 message getter。补无抛出格式化兜底，并用三个异常值验证成功／失败／成功的工具批次仍完整配对。
4. 单元测试里的半截流不等于真实传输证据。补发 text delta、半截 tool input 后发送 SSE error 的真实进程测试，证明未完成文本与工具都不会进入后续上下文。
5. 不把断言放在会被产品捕获的工具回调里：将观察值带回测试主体断言，避免断言失败被转换为工具错误后误判通过。

## 2026-10-01：多轮与基础压缩合并后的复盘

- **原史与发送视图必须分开。** 压缩后的摘要用于工作上下文，完整工具结果仍保留；失败不能抹掉副作用证据，窗口恢复不能重跑完成的工具。
- **所有请求都要计数，单位不能混淆。** system、schema、消息和输出安全空间共同占预算。摘要请求也要分块；summaryTokens 是输出 token 上限，UTF-8 字节紧凑目标是另一条约束，采用前还要对完整主请求计数。
- **软阈值不是硬失败。** 固定提示占比高时，无法达到目标水位并不代表请求不能发送。自动前台摘要失败但请求仍在硬预算内可继续；超限、计数失败或取消则不能放行。
- **可取消必须覆盖计数。** 只中止摘要网络请求不够；立即取消后的异步续体不能再启动新的计数。稳定前缀快照和代次检查共同阻止过期结果覆盖增量。
- **可回读要用真实读工具验证。** 一个超长单行即使保存到文件，按行读取仍可能截断末尾。保留全文并额外生成 Unicode 码点切片 JSONL，才让既有 read_file 能渐进访问全部内容。
- **后台任务必须有所有者。** 静态 Agent.run 和无显式 Session 的 runLoop 在结束时取消摘要；长生命周期宿主负责自己的退出清理。
