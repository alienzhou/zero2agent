# E03-S001-multi-turn 复盘

## 结果

实现 Session / Turn / Loop 分离、跨轮完整历史、`/new` 与失败后的可继续状态。课程资料含源码调研、决策、五篇 Spec、跟练、延伸阅读与测试。当前为本地候选，未推送、合入或打 Tag；最终证据见[验收记录](../specs/E03-product-foundations/S001-multi-turn/details/03-verification-checklist.md)。

## 做对的事情

- 调研只围绕历史归属、重置、工具配对与失败展开，没有把成熟产品的持久化和队列整体搬进第一节课。
- 用 SDK 请求快照而非回复文字证明上下文延续；用真实 CLI + 本地 SSE 验证宿主与 SDK 集成。
- 工具执行后保留证据，明确回滚消息不能回滚文件；没有用“出错删整轮”的简单实现掩盖副作用。

## 暴露的问题与修正

1. 第一版 E2E 已输出“再见”，但测试仍握着输入管道，三项用例各自超时。测试端在最后一行后关闭输入，随后的契约测试通过。
2. 展示回调的参数与工具输入原来共用引用，异步回调还可能返回 rejected Promise。输入深拷贝、拒绝捕获和提交快照隔离使展示不再改变执行事实。
3. 独立审查发现 `String(error)` 也可能抛错：例如 `Object.create(null)` 或抛错的 message getter。补无抛出格式化兜底，并用三个异常值验证成功／失败／成功的工具批次仍完整配对。
4. 单元测试里的半截流不等于真实传输证据。补发 text delta、半截 tool input 后发送 SSE error 的真实进程测试，证明未完成文本与工具都不会进入后续上下文。
5. 不把断言放在会被产品捕获的工具回调里：将观察值带回测试主体断言，避免断言失败被转换为工具错误后误判通过。

## 完整复核补记

用户要求工程和课程分别完整复核。保持输入管道打开的退出测试表明，第一轮将超时全部归因于测试驱动并不充分：EOF掩盖了真实的退出缺陷。修复为完成后台清理后释放非TTY输入，并保留TTY语义。另修复空响应只入历史、不显示的问题。两项测试均先失败、后修复通过。

当前专项为33项Core与6项CLI测试，全仓288通过、25项跳过。课程补齐了可实际操作的失败恢复测试骨架、依赖前置与术语解释。测试通过仍不等于所有模型回复效果已验证，真实供应商模型与对外发布未执行。

## 仍保留的限制

未调用真实供应商模型，不把协议测试说成自然语言理解验收；没有新增长会话裁剪和持久化。`[Harness]` 说明是明确标注的上下文内容，不是安全隔离或可信审计日志。
