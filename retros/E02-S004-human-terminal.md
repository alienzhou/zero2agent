## Summary

让人直接操作 bash 命令，并在结束后回到 Agent。core 保留默认 terminal，增加人工接管宿主契约；TUI 负责确认、PTY、输入独占、恢复与进程清理。CLI 和 REPL 共用这条路径，正文不进入模型回执。

这一章的主要增量不是“能写 stdin”，而是完整地借出并归还终端。实现参考 Aider 的人工交互、pi 的 TUI 恢复和 Gemini 的 PTY 路由，但没有照搬默认 Yes、正文捕获或后台面板。

## What Went Well

- 把原理放在 Story 前面，先说明人、宿主和 PTY 的关系，再解释接口和限制。
- 保持八工具集合，默认非交互路径有独立真实命令回归；人工路径不创建 OutputSink。
- 真实 PTY 测试发现了 mock 看不到的问题：双重换行、一次性 CLI 不退出、退出期输入泄漏、物理断连后异步清理停滞。
- 独立 CLI 无需模型配置，可以先验证终端能力，再验证 Agent 接入，降低验收成本。
- 锁文件收敛为精确 PTY 版本及平台二进制，去掉安装工具产生的无关 peer 图变化。

## What Could Be Improved

- 最初把“交互”理解成模型持续决策；五问和原理导读沿错误操作者展开。用户再次指出“让人操作 bash”才纠偏。应先问清谁看画面、谁输入，再设计协议。
- 第一版恢复只关注 raw mode，没有保存完整设备属性。双层 PTY 的 OPOST 重复转换，让输出出现额外回车；后来改为 stty 快照与还原。
- 程序退出后曾先卸载输入转发再清理，私人按键可能流入 readline。输入所有权必须覆盖整个退出窗口，直到恢复前排空缓冲。
- 根进程退出不代表进程组为空。以根 PID 存活决定是否继续清组，会漏掉两次扫描之间创建的后代。
- 最初用合成事件推断挂断效果不够。真正关闭外层 PTY 后，宿主可能卡在终端 I/O 或恢复路径；最终增加不依赖异步 drain 的同步退出分支。

## Lessons Learned

1. **先定义操作者，再定义会话协议。** 人工接管和模型多轮续写共用部分底层能力，但反馈、隐私和控制权不同。
2. **输入租约包含确认、运行和清理。** 私人窗口不能只覆盖子程序活着的时间；恢复前丢弃输入是显式隐私取舍，不是意外丢键。
3. **控制字符不是生命周期 API。** Ctrl-C 可能被捕获，Ctrl-D 可能只结束一次读取；需要独立的宿主中止键。
4. **所有权比“这个 PID 还活着”更重要。** 跟踪进程身份、组与已观察后代，并把组级兜底和无法保证的逃逸写清。
5. **断连不等于普通取消。** 终端已经消失时，没有可恢复的设备，也不应继续写结束提示或等待其 drain。
6. **验证要以就绪事件为时钟。** S003 旧 PTY 测试从 Python 启动计时，可能在 shell 初始化完成前发键；改为生产输入监听就绪后计时，未放宽断言。
7. **信号退出不能附带成功退出码。** native 事件可能同时给 signal 与 exitCode=0；应优先表达信号，CLI 用 128+signal。

## AI Coding Notes

- 接续已有 core 契约实现，按 core/TUI/真实 PTY/文档分工；审查发现的问题必须落实为真实回归，不把审查意见本身当通过证据。
- 所有秘密输入测试使用虚构 token；测试“未采集”时同时检查模型回执、readline history 和输出文件，而不是只看屏幕未回显。
- native 故障用明确注入，不能假设某个 cwd 一定使 spawn 抛错；最终物理断连测试调用未插桩 CLI。
- 保留用户已有 `.discuss/.snapshot.yaml`，提交只包含本任务文件。没有推送、修改远端或打 Tag。
- 协作记录、任务清单和导航随本轮补齐，避免 S003 已出现的“代码完成、读者入口仍写未开始”。
