# E04-S004：恢复以前，先说明哪些事实已知

本课最大的选择是复用完整会话 generation。逐工具 WAL 可以减少写放大，但会增加执行记录、原史、结果来源与最终快照之间的拼接协议。首版把这些信息放在同一份不可变版本内，故障时更容易判定恢复依据；代价通过 32 MiB 单份和 512 MiB/2048 份单会话门槛显式限制。

第二个选择是明确区分未执行、已结算和未知。执行标记发布后即使工具还未真正调用，也只能保守归为未知。消息协议需要配对，并不意味着可以编一个工具成功结果；中断占位明确标成宿主记录。

第三个选择是把恢复和开始新工作分开。读取记录不执行工具；继续需要用户明确的新指令和新预算。S003 的读取与产物检查必须保留，否则一个重启就能绕过完成门槛。

验证使用真实子进程退出和新进程加载，检查文件与副作用计数。真实服务只跑一组固定双文件任务用于集成，不靠反复重跑取得好看的分数。所有运行目录和截图从一开始就放在 tmp，Git 保留实现、测试、复现脚本、精简汇总和课程文件。

初期回归夹具曾使用不支持的文本产物契约、无效的结果引用，以及位于工作区内部的 Checkpoint 存储；分别修正为现有 JSON 契约、真实结果正文和隔离存储后重新验证。原失败日志保留在外部证据归档，没有通过放宽生产边界让测试通过。

最终复核发现一个展示边界：查看并保存中断会话会清除宿主 pending，但 recovery 仍未解决。会话列表现在同时检查两者；四个真实退出点都验证保存后仍显示未结算、成功继续后才清除。修复前的失败断言与修复后的结果另存外部证据包。
