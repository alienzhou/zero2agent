# E05-S003：外部工具要进入同一条执行链

MCP 协议负责连接与消息格式，宿主仍负责启动信任、具体调用授权、输入输出边界与恢复。本节把本地 stdio 服务适配为现有 Tool，复用权限、预算、长结果存储和配对恢复，避免建立第二套独立执行通道。

最重要的两个判断是：readOnlyHint 不授予本地读权限；没有收到工具结果也不能推断没有效果。真实服务在写入一次计数后退出/挂起，测试核对计数始终为 1，剩余项未执行，显式恢复不会重放旧调用。自查发现清理异常可能覆盖 unknown 异常，已修复为无论清理是否报告失败都保持未知语义，并补回归。外部来源累计容量也移到调用前核对，避免结算后才失败；能力提示按 MCP 启用状态切换，普通会话保留原请求文本。

长结果继续使用 E04 的引用，但仅检查临时落盘路径不足以代表来源权限。新增不含命令、环境与凭据的 ExternalSource，结果与历史目录各自版本化，磁盘会话 v4 明确保留新数据；旧普通会话不必升级。当前服务停用、配置身份变化或权限拒绝时，不从保存正文绕过授权。

最终审查把故障组合起来验证，发现单独的断线、保存失败和清理失败测试还不够：unknown 回执落盘失败会误标 settled，最外层关闭还可能覆盖未知错误并漏掉预算/运行状态释放。新增 3 个先失败后通过的回归，保留未知状态并以 finally 释放本地所有权。业务效果仍为一次，后续调用未开始。

初轮完整回归的 5 个失败是旧测试把新 v2 目录视为非法版本、以及精确执行上下文断言缺少新增字段；更新断言后通过。首轮真实模型的行为检查通过，但启动与构建重叠使一个运行文件哈希不一致，保留为历史观察，不作为当前构建证据；后续在构建完成后使用相同冻结输入补跑。所有模型观察与源码范围分别留在紧凑验收索引。

课程按实际问题安排 11 页，连接时序、权限两道门、结果流和故障计数各有独立图解。JSON 配置、完整参数表与故障矩阵放到跟练；阅读检查修正了一个结果列的拥挤和末页的 SVG 越界，保留字号与留白。
