## 一份日志怎样成为可信的定位入口

上一课保存了对话，仍然缺少运行边界。本课在实际 SDK 调用与原生工具结果处采集事实，由 Core 生成操作/请求身份，由宿主负责本地存储和展示。运行日志、模型上下文和可恢复快照各自独立，让无 API key 的读者也能定位已发生的工作。

最有价值的决定是先确定不采集的正文，再实现元信息白名单。复制全部对象然后删字段容易遗漏 SDK 错误、工具参数和人工终端字节。当前结构只接受已知标量，额外过滤环境中的密钥标签；日志依然包含时刻、身份和用量，教材没有把它描述成完全匿名。

## 后台工作需要捕获父身份

转后台命令和摘要可能晚于下一轮完成。如果回调到来时再问“当前 requestId 是什么”，就会把上一轮结果归错。本课在启动边界捕获 operation、request 和 session，允许结束后的原操作继续收到晚到事实；真实 PTY 实验核对了进程退出与生成文件。

## 可选观察接口也有兼容契约

完整回归发现，未启用诊断时也附加 onResultMetadata 会改变既有工具上下文的精确形状。修正为按需附加后，保留原断言验证；没有通过放宽旧测试把兼容问题遮住。

查看器采用独占焦点，支持滚动和返回。其引入暴露了测试中的操作假设：不能在只读视图中直接发送下一轮，也不能在模型文本出现时就认为宿主已完成保存。原 Ctrl-X/Ctrl-S 用例单独运行通过，全套中偶发赶在收尾之前；改为等待界面真实完成，再继续检查 PID 与清理。忙时 Enter 保留草稿的生产协议继续有效。

## 用运行边界定位模型停滞

真实服务两次拒绝同一条回归里的第二个新写入请求。请求证据显示模型只有文字回答，没有 tool_use；宿主审批代码没有接到请求。它将“不要自动重试已拒绝的请求”理解为会话内永久禁止工具。

补充工具策略说明：发起调用后由宿主判定权限并询问；一次拒绝不能被模型自行重试，但用户明确另提不同目标的新请求仍可发起，继续经过宿主审批。权限策略和验收的文件效果断言都保持原样。这是本课追查线索帮助修正既有交互的实际例子，真实服务结果仍以复验附件为准。

## 失败也要留下证据

队列/文件预算达到时停止接纳，已接受队列继续写入；实际 I/O 错误让界面持续显示降级，任务继续。正常结束会 flush，但这不是文件工具和日志的联合事务。强制终止后，完整行可以追查，未闭环只表示结果未知，不能触发自动重放。

初始完整回归和修正后的失败报告都保留，夹具、PTY、真实服务和人工审阅分别记录。最终结果与源码哈希以验收页和 summary.json 为准。人工审查、课程部署和 S006 文件 Checkpoint 不由自动验证代办。
