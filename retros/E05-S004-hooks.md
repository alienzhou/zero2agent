# E05-S004：检查结论不能覆盖工具事实

本节复用原权限、预算、文件保护、结果和恢复，不把展示回调变成控制接口。beforeTool 在批准之后运行，afterTool 等真实回执保存，beforeComplete 与原读取/产物门槛共同决定完成。程序只有 pass/block，不批准或改写参数。

真实 SIGKILL 暴露出两个需要直接处理的边界：宿主 finally 不会运行，检查必须由父管道守护终止；回执保存与后置检查启动之间的窗口，也必须在同一次保存中留下“尚未检查”。工具与检查分别结算，不能在恢复时凭空补一张成功回执。

旧检查 unknown 不会自动补跑；用户核对后新建独立检查，保留原记录。脚本需要修正时，新版本必须重新信任，同 ID/阶段的替代仅在用户显式 recheck 时采用。普通继续或删除配置不能解除必要检查。

组合离线 v1 首次撞到工具预算：目录规则补载使整批两项读取未执行，随后还需要最终契约读取。保留该失败，在真实模型前将 v2 固定为首次单调用发现作用域，再按当前规则成对读取；预算始终是 8 请求/12 工具/120 秒。原输入与修正的 SHA、源码和原始记录分别保留，不能只留下最后一次通过。

v2 的模型文字指令仍不足以控制批次：ee371e1 正例将 tail 与两个 API 读取一起提交，整个未执行批次计入预算，报告尚未开始就停止。宿主已经知道任务目标，应提前提供规则；增加明确初始目录能力，按当前权限和物理边界加载，而不是继续改提示词赌模型遵从。冻结原 v2 输入与预算，用同源码只切换初始目录的成对评测记录这一修正，首请求覆盖层变化明确披露。

最终实现复核补上数组型受控路径、内部文件审计的当前许可、后置元信息容量的副作用前预检、停止调用的展示终态与重新检查的结构化事件。测试分别确认真实文件、原回执、进程 PID、诊断隔离和未完成门槛，避免只判断错误字符串。

课程使用 12 页，每页新增一个必要判断：三个检查点、版本信任、事实分离、最小协议、进程守护、恢复与组合验收。完整配置和参数下沉到跟练，原始截图和实验记录只在 Git 外归档。
