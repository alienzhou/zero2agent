# E04-S002 复盘：已有落盘，还缺少可读取的契约

[课程](../specs/E04-reliability-and-context/S002-result-references/README.md) | [验收](../specs/E04-reliability-and-context/S002-result-references/details/03-verification-checklist.md)

用户首先指出，这可能与终端大输出重复。核对源码确认：终端已经流式保存，ContextManager 也会在压力下替换正文。新增价值应落在引用、当前授权、范围、校验和生命周期，而不是再写一个临时文件助手。

实现把结果正文与调用身份分开：SHA-256 标识字节，reference 标识当前会话的一次来源。终端在既有流关闭后封存，不把大文件读回内存再写一遍。新结果从历史入口就使用引用，旧历史只改变发送视图，减少对已有会话契约的破坏。

两个真实问题靠回归暴露。其一，macOS 的 /var 别名加上尚不存在的存储父目录，导致最初的目录校验误拒绝终端执行；修正为先解析配置父路径的真实已有祖先，再检查私有存储子树。其二，原测试把工具总数固定为 8，增加读取工具后需更新为 9，同时保留已有工具断言。失败输出与修正记录保留在 acceptance 中，没有调整终端等待时间来掩盖错误。

按字节读取还要求分清有效 UTF-8 字符内部与本来就非法的字节。新测试加入四字节字符与非法字节混排，分别验证范围错误、next_offset 和 raw_base64。测试夹具最初手写错了一个 UTF-8 字节，修正的是夹具，不是解码器。

独立进程测试比同一对象 restore 更有说服力：每个来源创建、恢复、拒绝、删除后读取，检查实际请求和正文哈希；真实模型再从未知随机答案中取证。两层证据分别报告，不把本地固定响应叫成模型实测。

本版每次回读都会流式校验完整正文，I/O 随正文大小增长。过期正文按会话懒回收，没有全机后台清理；未封存后台文件和遗留写锁需要人工处理。这些边界进入课程，避免把本地有限存储包装成通用对象存储或崩溃恢复系统。
