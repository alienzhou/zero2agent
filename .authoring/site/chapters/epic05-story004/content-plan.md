# 12 页学习路径

目标：能把检查接入现有执行链，并解释工具事实、检查事实和恢复义务。采用封面加 11 个必要步骤；18 页只是上限。

1. 总体关系：已写入与检查失败可以同时成立。
2. 项目规则、技能与程序检查的区别。
3. 三处同步检查点及保存顺序。
4. 当前配置/脚本身份与显式启用。
5. 权限、前置检查和文件保护的顺序。
6. 后置失败保留真实回执及效果。
7. 原读取/产物门槛与文件审计。
8. 最小 JSON 契约和输出隔离。
9. 宿主 SIGKILL 后的进程守护。
10. 两本账与显式新检查。
11. 四种扩展的完整证据链。
12. 正常流程、两种故障及跟练入口。

不另设概念综述、功能回顾或收官总结页；容量全集、完整 JSON、SDK/CLI 语法和故障矩阵放在跟练与 Spec。保持原字号、1080×1440 画布及留白。
