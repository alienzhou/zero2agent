## 正文

本期是 Zero2Agent 系列的第三课，聚焦文件搜索功能的实现，以及背后的技术选型方法论。

**一、find_files：补齐 Agent 的基础工具集**

现有的 grep_search 解决的是「内容搜索」，但 Agent 经常需要回答「哪些文件匹配某个模式」。这是两个不同的搜索维度，需要专门的工具来支持。

实现过程中遇到的一个关键问题是路径解析：工具内部统一使用绝对路径，避免依赖 process.cwd() 的隐式假设。这引出了本期第三个主题 ToolContext 的设计。

**二、Benchmark 驱动的技术选型**

技术选型不能仅靠定性分析。本期针对文件搜索工具设计了完整的 Benchmark：

- **候选方案**：rg --files、fd、npm glob、fs.glob（Node 22 原生）
- **测试维度**：全量列文件、指定后缀过滤、多扩展名匹配
- **语料选择**：小/中/大三个量级的真实项目（6k / 50k / 200k+ 文件）

实测结果：rg/fd 在 10ms 级别，npm glob 约 60ms，差距达 5 倍。当性能差异达到一个数量级时，数据比主观判断更有说服力。

方法论层面，总结了一套可复用的选型流程：竞品调研 → 定性分析 → Benchmark 验证 → 结论解读。

**三、Agent Debug 五层模型**

调试能力是 Agent 可靠性的关键。本期将调试能力抽象为五个层级：

1. 纯静态分析（门槛最低，天花板也最低）
2. 预埋日志（基础保障，需要开发阶段规划）
3. 动态日志（当前实践的「性价比」选择）
4. CDP 简单调试（具备实时性，但需本地环境）
5. CDP 高级能力（理论上可达高级工程师调试水平）

动态日志的核心思路是：Agent 分析代码后生成假设，在关键路径插入日志埋点，复现问题后读取日志验证假设，最后基于确认的假设进行修复。这比让 Agent 直接猜代码问题要可靠得多。

**四、ToolContext 工程基座**

随着工具数量增加，隐式依赖（如 process.cwd()）迟早会成为问题。ToolContext 是一个统一的工具运行环境，本期先聚焦 cwd 的标准化注入，为后续所有工具建立一致的上下文契约。
