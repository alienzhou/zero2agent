# E03-S001 逐页内容规划

18张含封面；延续原一期与系列视觉。情景→原理→实现→验证→跟练。每页核心问题必须在图内正文回答，不能只登记来源。

| 页 | 核心问题 | 正文与画面 |
|---|---|---|
| 01 | 本期做什么？ | 多轮会话与上下文压缩；开场追问对话。 |
| 02 | 一句接着做依赖什么？ | 上一轮依据与当前问题。 |
| 03 | 第二轮请求带什么？ | 尚未压缩的纯文本消息顺序示意。 |
| 04 | Session、Turn、Loop各管哪层？ | 嵌套生命周期图。 |
| 05 | 谁持有跨轮历史？ | Agent复用Session与实例隔离。 |
| 06 | 工具证据怎样成对？ | tool_use / tool_result用ID配对。 |
| 07 | 文件改了、回复失败，留什么？ | 完整历史留证据；发送视图可压缩。 |
| 08 | 半截输出能入史或执行吗？ | 流中断与输出截断的不同边界。 |
| 09 | /new重置什么？ | 历史、摘要、替换视图与后台压缩；环境不回滚。 |
| 10 | 完整请求怎么算预算？ | system、工具定义、消息、输出与安全预留；两种计数。 |
| 11 | 三个水位怎样自动分级？ | 45/65/85%输入预算；先缩短大结果到私有可回读文件。 |
| 12 | 后台摘要怎样不覆盖新消息？ | 稳定配对前缀、保留尾部、前台等待接管、代次核对。 |
| 13 | 用户怎样主动压缩？ | /compact前台命令与SDK compact/getContext/getHistory。 |
| 14 | 哪些情况必须停？ | 超大当前输入、摘要失败、有限超限恢复，不重跑工具。 |
| 15 | 摘要请求自身如何不过载？ | 分块计数、分层合并、调用上限与事实交接。 |
| 16 | 怎样验证而非靠模型自述？ | 本地HTTP/SSE请求矩阵，协议与模型效果分开。 |
| 17 | 如何在根目录跟练？ | 启动配置、追问、/compact、/new与旧版本限制。 |
| 18 | 本期形成什么能力？ | 完整记录与有界发送；内存边界；下期权限与Approval。 |

不做会话持久化、分叉、沙箱或摘要质量评分。自动压缩的45%是目标，不保证达到；任意大当前输入不能无损硬塞进窗口。候选仍待确认，18页待主会话逐页审图。
