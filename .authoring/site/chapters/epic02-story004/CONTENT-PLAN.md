# E02-S004 内容规划 · 情景教学版

受众：有编程基础、想实现 Agent Harness 的开发者。目标：从一段真实操作理解人的按键如何连接到 bash/子程序，以及输入如何安全交接与归还。

13 页含封面，maxImages=18。保持现有系列配色、字体、封面与页眉；原理仍在第 3 页。普通命令不能原地升级成人工接管，模型续写、Windows 支持和完整沙箱均不在本课内。

| 页 | 成稿标题 | 本页的新信息与表达方式 |
|---|---|---|
| 01 | Agent 会跑命令，我来接着操作 | 以人的连续操作为切入点，封面保留双边框、斜纹、三标签。 |
| 02 | 先试一下：让 Agent 等我操作 | 先展示 Node 的两次输入与返回，让读者知道做完能得到什么。 |
| 03 | 追踪一次按键：42 是怎么回来的？ | 追踪 n * 2 / 42，通过真实字节示例理解人、宿主、PTY、子程序。 |
| 04 | 都有 stdin，为什么还需要 PTY？ | 给出可复现的 pipe/PTY 启动与检测方式，比较 false/true。 |
| 05 | 按下 y 之后，才真正把键盘交过去 | 用拒绝/批准两条分支解释何时启动，注明一次确认的范围。 |
| 06 | 接通输入和输出，代码里是哪两条线？ | 两段连接伪代码解释输入/输出方向，三个入口缩成旁注。 |
| 07 | 我刚输入的内容，模型能看到吗？ | 并排展示人的终端与模型工具回执，另分清直接入口只本地显示。 |
| 08 | 按 Ctrl-C，为什么不一定回到 Agent？ | 通过真实 Ctrl-C 清空半行的现象讲按键，再区分直接启动与嵌套 bash。 |
| 09 | 程序退出了，下一句话发给谁？ | 用晚到 abc 的情景推演解释为何清理期仍需独占输入。 |
| 10 | 原命令退出了，子进程也一定结束了吗？ | 用后台 sleep 示例解释原命令退出后为何还要检查后代。 |
| 11 | 怎么知道接好了？别只试一句 Hello | 把测试矩阵改成三个可观察现象；平台限制与异常边界保留。 |
| 12 | 现在自己试：计算一段，翻几页文档 | 把最小姓名演示升级为连续计算与分页搜索，写清每层退出方式。 |
| 13 | 再看开头那次操作：我们给 Agent 加了什么？ | 回到开头三种体验，将它们分别对应到宿主实现；不编造发布入口。 |

三页试排（2、3、9）先验证操作展示、链路解释和问题推演，再扩展到全套。独立复核补齐了直接入口回执、嵌套 bash 退出和第 4 页复现实验步骤。

本轮观察与跟练修订保留这份页序与标题；以提示符对照、两条退出路径、实验排查方向和输入/输出分栏代替部分解释段。最新逐页变化见 [REVISION-NOTES.md](./REVISION-NOTES.md)。首次试排第 2、5 页超出内容容器，删去重复引言与压缩说明后重新导出；不缩小全套字号。
