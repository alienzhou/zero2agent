## 对本课的设计推导

1. **事件先于动画**：等待模型、工具开始/结束/错误、权限等待/结算、压缩和整轮终态由运行时报告。不能靠“5 秒没输出”判定卡死，不能给未知总量的任务编造百分比。
2. **整轮与工具分开**：turn ID 归属一次运行，call ID 区分同名工具。工具完成后仍可能继续请求模型。completed、failed、cancelled 应有不同显示。
3. **展示与控制分开**：通知异常不能改变执行结果；批准/拒绝是关联请求 ID 的控制通道。待决请求失效后，晚到的批准不能执行工具。
4. **一个时刻一个输入接收者**：对话输入、审批、人工 PTY、退出清理有独立焦点。人工终端期间暂停普通输入与状态重绘，恢复后保留正确草稿；私密输入不进入对话和历史。
5. **取消沿执行链传播**：模型请求、权限等待、支持取消的工具共同响应。未开始工具不继续执行；不能仅靠 Promise.race 就宣称副作用已停止。取消也不自动撤销已有文件修改。
6. **忙时交互要可预测**：允许编辑就必须保留草稿与游标；提交采用明确的排队或提示策略，不能吞掉输入。TUI 改进应落到可编辑输入、历史、粘贴、补全、工具详情和窄屏可用性。

这些是本项目的设计判断，不是四款产品共享的标准。[implementation-options.md](./implementation-options.md)比较原生终端、Ink、OpenTUI 与 Ratatui；最终能力由 Spec、代码和实际验收证明。

## 由调研推导的验收场景

这是待验证矩阵，不是通过记录。

| 场景 | 判据 |
|---|---|
| 模型首字延迟 | 显示等待，取消终止请求或后续调度 |
| 文本→工具→文本 | 顺序正确，工具成功不等于整轮结束 |
| 同名工具连续执行 | 参数、状态、耗时按调用关联，不串结果 |
| 审批批准/拒绝/超时/取消/EOF | 只有当前有效批准能执行，其他分支结算后恢复正确焦点 |
| 模型、审批、前台命令期间取消 | 停止当前工作，未开始工具不运行，结束后能继续新轮 |
| 已有后台任务时取消 | 后台生命周期遵守既有终端契约 |
| 人工 PTY 输入后退出 | 普通输入和重绘暂停，输入不进入对话/历史，终端模式恢复 |
| 压缩、断流、工具失败 | 提示不污染模型正文；迟到事件不覆盖终态；消息配对完整 |
| 多行粘贴、中文、历史、slash 补全 | 预期输入可完整编辑和提交，控制键不误触审批或退出 |
| 窄屏、resize、控制序列 | 不破坏提示与焦点，不能用输出伪造宿主界面 |
| 非 TTY / 重定向 | 无游标重绘垃圾，不把管道后续文本当审批回答 |

权限规则本身参见 [上一课调研](../permissions/README.md)。本期聚焦把运行事实与用户控制衔接起来。
