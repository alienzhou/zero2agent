# D01：会话所有权与失败契约

状态：实施采用，2026-10-01。基于用户已授权的课程边界，由 Agent 完成技术取舍；不代表用户逐项审查通过。

## 高层问题

1. “连续输入”为什么不是多轮对话？现有 Loop 每次创建单条 user 数组，上一轮最终回答也未写入历史。
2. 谁持有历史？Session 是内存历史和互斥边界；Agent 持有一个 Session；Turn 是一次用户请求；Loop 是 Turn 内多次模型／工具交互。
3. 错误后保留什么？成功完成的请求、assistant 内容与工具结果必须可追溯；工具副作用不会随异常回滚。
4. `/new` 清空什么？只清空当前进程的对话历史，不撤销文件、不杀后台进程、不删除日志、不保证外部服务忘记内容。

## 方案对比

| 方案 | 判断 |
|---|---|
| CLI 拼接聊天字符串 | 拒绝：丢失角色、工具 ID 和结构化结果，其他宿主无法复用 |
| 全局 messages 数组 | 拒绝：实例间串话，无法隔离工作目录 |
| Agent 持有 Session，Loop 执行一轮 | 采用：所有权明确，静态调用仍可保持一次性 |
| 出错删除整轮 | 拒绝：文件可能已改，模型失去工具证据 |
| 保留完成消息及工具对，以宿主说明收尾 | 采用：不自动重试，不伪装模型完成任务 |

## 接口与边界

- `new Agent()` 创建独立会话；`agent.run()` 延续历史，`agent.reset()` 新建对话，`agent.getHistory()` 返回深拷贝供检查。
- `runLoop(message, { session })` 可显式复用 Session；不传则一次性；`Agent.run()` 静态调用仍一次性。
- 同一 Session 同时只能运行一轮，运行时 reset 拒绝；不同实例相互独立。
- 固定 Agent 创建时的 cwd，避免运行中宿主切换目录导致历史与工具所见项目不一致。
- 完整 tool_use 响应与所有 tool_result 配对；工具错误有 `is_error`。事件通知失败不得打断工具账目或改变执行结果。
- max_tokens 不执行工具，补失败回执；部分文本可保留但标注截断。达到迭代上限补明确说明。
- 网络／流式错误保留完成前缀，加通用 Harness 中断说明后继续向调用者抛错；不把原始异常细节注入模型历史。
- 本课不新增全局取消 UI；既有 terminal 取消仍按工具回执处理，进程退出后会话丢失。
