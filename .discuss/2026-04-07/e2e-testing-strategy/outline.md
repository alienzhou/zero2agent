## ✅ Confirmed

### D01: 测试分层策略
- **Core 层**：单元测试为主，Mock LLM 响应，验证工具调用逻辑
- **TUI 层**：端到端集成测试，真实运行完整流程
- **LLM 调用**：真实调用，但控制比例（非每次 CI 都跑）
- **验证方式**：行为验证（验证调用了什么工具、工具输出特征），非精确输出匹配
- **文件系统**：临时工作区隔离，setup/cleanup 机制

### D02: 端到端测试场景分类
**单轮功能验证**：
- 创建文件 → 验证调用 write_file 工具
- 搜索内容 → 验证调用 search 工具

**多轮上下文验证**：
- 第一轮：让 Agent 输出特定内容
- 第二轮：基于第一轮继续追问
- 验证：第二轮输出能引用第一轮信息，证明上下文连通

### D03: 比例控制策略
- **控制用例数量**：只测关键流程，不追求覆盖率
- **触发方式**：手动触发（非 CI 自动跑）
- **验证机制**：先用简单的输出/文件系统验证，后续再加 Hook

### D04: 验证机制选型
- **当前**：简单的端到端测试，通过文件系统状态 + 输出内容验证
- **后续**：等实现 onToolCall Hook 后再增强可观测性

### D05: 黑盒测试设计模式
- **三步法**：确定目标 → 设计提示词 → 检测结果
- **不深入内部实现**：只看输入输出

### D06: MVP 测试用例清单
| # | 测试目标 | 提示词任务 | 结果验证 |
|---|----------|------------|----------|
| 1 | 文件读取 | "读取 package.json 的内容" | 输出包含项目名称 |
| 2 | 目录列表 | "列出 src 目录下有哪些文件" | 输出包含已知文件名 |
| 3 | 内容搜索 | "在代码里搜索 Agent 类的定义" | 输出包含 class Agent 或文件路径 |
| 4 | 文件查找 | "找出所有 .ts 结尾的文件" | 输出包含 .ts 文件列表 |

**注意事项**：
- 当前只有读能力（read_file, list_directory, grep_search, find_files），暂无写能力
- 此为临时 MVP 方案，后续会增强为更全面、健壮的测试体系
