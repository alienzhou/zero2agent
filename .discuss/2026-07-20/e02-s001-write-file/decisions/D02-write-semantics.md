# D02：写入语义 —— 全量写入 + 自动创建父目录

## 状态
✅ Confirmed

## 决策

`write_file` 的语义收敛为最简单、最可预测的形态：

- **全量写入**：给定 `path` + `content`，把 `content` 作为文件的完整内容写入。
- **不存在则创建，存在则覆盖**。
- **自动创建缺失的父目录**（等价 `mkdir -p`）。
- **不做 append、不做 mode 开关**：局部追加/修改留给未来的 `replace_in_file`（S002）。

## 竞品对照

去掉各家工程复杂度后，write 的「最小闭环」高度收敛，五家一致：**`{path, content}` + 自动建父目录 + 不存在建/存在覆盖**。

- **pi-mono** 几乎就是这个裸形态，是 S001 的直接蓝本。
- OpenCode / Gemini 也都是「单一全量写、无 append」，并在工具描述里引导「局部改动用 edit，别用 write」。

## 理由

1. **单一职责最利于教学**：一个写工具只做一件事——把内容整体落盘。语义越单一，读者越容易理解，模型越不容易用错。
2. **append/局部改是另一种能力**：它们有各自的边界与坑（定位、幂等、冲突），塞进 write 会污染语义。Roadmap 已为此规划了 S002 `replace_in_file`。
3. **自动建父目录是零歧义的便利**：五家都这么做，避免模型为了写 `a/b/c.txt` 还要先显式建目录。

## 参数形态（进 Spec 时定稿）

```
write_file({ path: string, content: string }) => string
```

- `path`：相对路径按 `path.resolve(ctx.cwd, path)` 解析（沿用现有 4 个只读工具的惯例）。
- 回执见 D06；路径安全见 D03。
