# D03：全量替换 —— replace_all 开关（默认 false）

## 状态
✅ Confirmed

## 决策

提供可选参数 `replace_all: boolean`，**默认 false**：

- 默认（`false` / 缺省）：要求 `old_string` 唯一匹配（D02），≥ 2 次报错。
- 显式 `true`：替换文件里**所有**匹配处，回执报告实际替换处数。

## 竞品对照

五家竞品在单文件 edit 里**都没有** `replace_all` 开关——重命名变量要靠模型反复调用 `edit`（或写补丁）。这是 S002 的一个**有意的小偏离**。

## 理由

1. **真实高频场景**：「把 `foo` 重命名为 `bar`」本应一次完成，没有 `replace_all` 却要 N 次调用，浪费 token 与迭代轮次。
2. **低成本实现**：`split(old_string).join(new_string)` 一行搞定，不增加设计复杂度。
3. **默认守住安全**：默认 `false` 维持唯一性约束这个安全默认；只有模型显式声明「我知道会改多处」才放行全量替换——把「批量替换是有意为之」显式化。
