# D04：Agent 工具设计方法论

## 状态
✅ Confirmed

## 决策

从零设计 Agent 工具时，按以下框架思考：

### 核心原则

> 对人好用的工具对 AI 也好用，反之亦然。

不存在"为 LLM 特殊设计"——好的工具设计天然对两者都友好。工具太复杂，对人繁琐，对 AI 也容易出错。

### 四个核心问题

1. **工具解决什么问题？** — 明确使用场景和核心价值
2. **LLM 需要控制什么，什么应该自动化？** — 决定参数设计。暴露必要的控制点，自动化合理的默认行为
3. **工具在工作流里的位置，输出契约是什么？** — 工具不是孤立的，要考虑它在 agent 工具链中的上下游关系，决定返回什么信息、什么精度、什么格式
4. **边界情况怎么兜底？** — 量的边界（结果太多/太少）、质的边界（输入不合法）、资源边界（超时/文件太大）

### 适用范围

- 这个框架适用于所有 Agent 工具的设计，不仅限于 grep_search
- 不同工具有各自的特异性，但基本思考路径一致

## 理由

作为教学项目，方法论的价值和功能实现同样重要。学习者不仅要知道"怎么实现 grep_search"，还要掌握"如何从零设计任意 Agent 工具"的通用思路。
