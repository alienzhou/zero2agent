# D02：从简陋 CLI 到可连续使用的 TUI

[讨论](../outline.md) | [设计](../../../../specs/E03-product-foundations/S003-runtime-tui/details/01-technical-design.md)

用户补充：“这一课是不是应该做到交互比较良好的 TUI 啊，你可以看看其他很多 CLI/TUI 类型的 Agent 工具呢（之前的 CLI 比较简陋）”。因此验收包括操作效率、可发现性与视觉层级。

## 连续任务场景

1. 空闲时输入两行中文，左右移动并修改；粘贴多行代码后仍留在编辑器，由用户显式发送。
2. 输入 / 出现可发现的命令提示；Tab 补全命令；上下键能找回历史且保留当前草稿。
3. Agent 请求、输出和执行时，阶段与耗时持续可见；可编辑下一条草稿，Enter 不误发起重入 Turn。
4. 两次同名工具分别展示状态；默认只显示摘要，按键展开详情、选择其它工具，长记录可浏览并回到底部。
5. 需要审批时明确显示工具、cwd、参数与理由；长参数能完整滚动；y 批准本次、n/Enter 拒绝、Ctrl-C 取消本轮。保留直接决策，避免强迫逐页翻阅。
6. 取消后保留草稿、已完成结果和明确的收尾状态；工具仍在收尾时不显示空闲。
7. 人工 PTY 接管、返回两次，输入历史中无私密终端正文，编辑器、游标和快捷键仍正常。
8. 常规宽屏、80×24、窄屏与 resize 后信息可读；工具输出中的控制码不能伪造审批或清屏。

## 呈现原则

顶部提供品牌/阶段与必要元信息；对话区域区分用户、模型、工具；审批提供醒目但节制的强调；底部是有边界的输入区与当前可用按键。快捷键提示随焦点变化，避免把所有命令一直挤在一行。

竞品借鉴依据收在 researches/runtime-tui/，本机观察、固定源码与文档分别标识。交互体验由生产 TUI 的真实 PTY和视觉检查证明。
