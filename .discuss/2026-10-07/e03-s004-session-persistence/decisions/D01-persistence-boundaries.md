# D01：保存可恢复的数据，重新建立运行环境

## 数据与时机

保存版本化 JSON：UUID、真实工作目录、创建/更新时间、标题、递增 revision，以及 raw messages 和已采用摘要/through。临时工具正文替换文件、后台压缩任务、权限决定、进程和凭据不进入快照。

每轮开始前先发布 pending 快照；正常、取消和失败结算后保存完整配对历史。崩溃只保证恢复上一结算边界；pending 提醒工具可能已产生影响，不自动重放。手动压缩结算后保存。

## 文件与并发

同一工作目录按 realpath 的 SHA-256 隔离。私有目录 0700、文件 0600。同目录临时文件写完并 fsync，再通过独占 hard link 发布不可变 revision；发布冲突在下一模型调用之前阻止执行。保留旧 revision，避免覆盖竞争和损坏证据；本课不做自动清理，明确磁盘增长成本。不支持无 hard link 的存储。

pending 记录进程 PID 和主机名用于识别仍在执行的旧运行：同机旧 PID 存活时拒绝恢复，其他主机的 pending 也拒绝。PID 复用可能保守拒绝，绝不恢复旧进程。空闲快照可以被多个进程读取，但只有一个能成功发布下一 revision。

## 交互与边界

交互和单次调用默认自动保存，可用 --no-save 禁用。--list-sessions 无需 API Key；--resume UUID / --continue 支持启动恢复；/sessions 为 TUI 选择器，plain 提供列表；/resume UUID、/session、/save、/new 支持同一会话控制器。现有 --plain、管道、单次消息、/compact、/terminal 与 --terminal 保持可用。

读取/校验完整快照后才替换当前历史；错误不改变当前会话。恢复工具调用只用于显示和下次模型上下文，决不调用工具。权限使用当前宿主策略。

存储失败时保留内存，显式提示未保存，/save 可重试；切换前先保存，失败则留在当前会话。不得把保存失败说成回滚。
