## ✅ Confirmed
- 现有四层结构本身是合理的，问题主要不在层级，而在层级之间的用户引导还不够强
- README 在"课程路线图"位置是第一个关键分流点，应该承担"开始学习"的职责，而不是只展示地图
- Story 页目前最接近真正的学习起点，因为它已经回答"先看什么、再看什么、重点看哪里"
- 仅按文档层级设计不够，还需要按用户身份设计路线
- "完全不了解项目的人"和"已经关注过项目的人"是两个优先级最高的核心用户画像
- 首次访问用户的路线终点应是进入某个 Story 开始学习，而不是停留在 Roadmap 或 Epic
- 回访用户需要的是更短路径，重点是"继续学习"或"查看最新进展"，而不是重新看项目介绍
- 第一版文档导航应先围绕"首次访问用户 / 回访用户"两类状态设计，而不是继续细分更多画像
- README 应承担总分流页职责
- "直接开始学习"和"继续学习"可以合并，不必作为两种独立入口
- 回访用户更适合按"进展"进入，而不是按"是否继续学习"进入
- 回访用户至少需要两条进展型路径：
  - 最新进展的快速入口，适合高频跟进用户直接跳到当前 Epic 或 Story
  - 查看近期进展，先看 `CHANGELOG.md`，再从变更记录进入对应 Epic 或 Story
- README 入口命名可沿用"第一次了解这个项目 / 查看近期更新记录"这一类文档导览式表达
- 对于快速入口，最终目标页应优先是推荐 Story，而不是 Epic
- 由于当前是 Markdown 文档形态，阅读体验应更多依靠文档内部互链来增强，而不是依赖产品式按钮交互
- Story 应至少支持回到所属 Epic 的链接
- 有关联的 Story 与 Epic 之间也应该补充交叉链接，帮助读者横向跳转
- P0、P1 和用户路径都重要，但应按用户路径逐块推进，而不是一次性铺开
- 导航区域采用单行面包屑式（`[A](...) | [B](...)`），避免平铺列表占用过多版面
