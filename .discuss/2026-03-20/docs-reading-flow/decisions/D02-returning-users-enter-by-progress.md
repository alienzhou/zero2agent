# D02：回访用户按进展进入，而不是区分“直接开始”和“继续学习”

## Status

Confirmed

## Date

2026-03-20

## Decision

对于回访用户，文档入口不再把“直接开始学习”和“继续学习”视为两类独立路径，而是统一为“按进展进入”。

第一版至少支持两类进展型入口：

1. 最新进展的快速入口  
   适合高频跟进项目的用户，进入后可直接跳到当前推荐的 Epic 或 Story。

2. 查看近期进展  
   先进入 `CHANGELOG.md`，再从变更记录跳转到对应的 Epic 或 Story。

## Why

“直接开始学习”和“继续学习”在回访场景里很难严格区分，因为不同用户的上下文差异很大：

- 有人是昨天刚看过，想快速续上
- 有人是一周后回来，想先知道最近更新了什么
- 有人虽然是回访，但这次想直接进入当前最新 Story

如果强行按“直接开始 / 继续学习”分流，入口语义会比较模糊；改为按“进展”分流，更符合回访用户的真实心智。

## Consequences

正向影响：

- `README` 的入口语义更清晰
- 回访用户不需要先判断自己属于哪种学习状态
- `CHANGELOG.md` 的导航价值会显著提升

需要后续补充的内容：

- “最新进展”入口具体链到哪里
- `CHANGELOG.md` 是否需要补全对 Epic / Story 的双向链接
- README 中这一分流区块的文案如何写得自然

## Notes

这一决策不影响首次访问用户的主路线，首次访问用户仍然以“理解项目 -> 进入学习入口”为主。
