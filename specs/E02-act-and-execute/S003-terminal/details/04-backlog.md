## 一、明示的已知缺口（有意保留）

这些在 spec 里如实写明，不假装解决：

| 缺口 | 为什么不修 | 依据 |
|------|-----------|------|
| **`setsid` 逃逸 killpg** | 要拦就得递归扫 `/proc` 找逃逸进程。能写，但会让这一章的重点从「理解生命周期」变成「一个大工程」 | D04-2 |
| **落盘文件无容量上限** | 这是 `/tmp` 本来就该负责的事；设上限会引入一个需要长篇解释的例外（「磁盘上限不算截断」），教学成本高于它防住的风险 | D04-11 |
| **非 TTY 下完全无人形兜底** | CI 跑 Agent 本来就该在外层套 `timeout 30m`。**这是 CI 的责任，不是工具的责任**——硬上限只会给假安全感 | D03-6 |
| **watcher 的 1 秒延迟窗口** | 轮询间隔的固有代价，孤儿最终会死 | D04-7 |
| **zsh rc 场景覆盖不全** | 完整方案 300+ 行，代码量超过工具本身，会让读者以为这一章讲 shell 兼容性 | D05-8 |

> 📌 **判据：修补的复杂度与教学价值不成比例时，明示缺口 > 假装解决。**
> 这条判据在本 Story 用了四次。

## 四、被拒绝的方案

| 方案 | 拒绝原因 | 依据 |
|------|----------|------|
| **截断输出**（五家竞品共识） | 把「上下文预算」问题当成「输出长度」问题解；留下的 200 行同样是模型没要求过的内容 | D02 |
| **默认超时 + 到点杀死** | 杀死不可逆，而「该不该继续等」只有人能判断 | D03-1 |
| **1 小时兜底上限** | 防不住它看似在防的任何一件事，只给假安全感 | D03-4 |
| **复用 Ctrl-C 做取消** | 人眼前看到的是 Agent 不是命令，赌输代价是整个会话 | D03-12 |
| **裸 ESC / 裸字母做快捷键** | ESC 被 ANSI 转义序列吞掉；字母键要留给输入 | D03-13 |
| **给模型 `list_processes` / `kill`** | list 的唯一增量信息是「别人起的进程」，恰是模型不该碰的 | D04-8 |
| **退出时一律杀掉后台进程** | 违背「跳过」的初衷 | D04-10 |
| **落盘设上限 / 退出时清理** | 与「不截断」立论冲突；且跳过的命令可能还在写 | D04-11 |
| **直接继承 `process.env`** | 前提「Agent 由用户终端启动」在桌面 App / 服务 / CI / cron 下全不成立 | D05-2 |
| **`TERM=xterm-256color`（跟 Gemini）** | 它的理由是驱动 pty 里的 headless emulator，我们不做 pty | D05-10 |
| **不设 `TERM`** | 最差选项：`tput` / `clear` 直接报错 | D05-10 |
| **`NO_COLOR=1`** | 既非必要又不充分 | D05-11 |
| **扩展 `ToolContext`** | 单一消费者 + 生命周期同进程，模块级缓存才是正确位置（第四次） | D05-12 |
| **返回侧加 metadata / 流式回调** | OpenCode V1 的 exit code 泄漏就是这么来的 | D01-5 |
| **固定名的隔离标签** | 实测可被命令输出伪造闭合串越狱 | D01-15 |
| **`bash -i`** | 交互模式会让 zsh 忽略 SIGTERM，要杀的时候杀不掉 | D01-4 |
| **`bash -lc` 执行用户命令** | `-l` 只用在采集那一次；执行时读 rc 会带来副作用与重复开销 | D05-3 |

## 五、Deep Dive 话题池

按可独立成文的价值排序：

1. **「进程杀了 ≠ 管道关了」** —— 终端工具最隐蔽的坑。一个 `setsid` 曾孙攥着继承来的 fd，就能让整个 Agent 挂死。Codex 专门为它加了 `IO_DRAIN_TIMEOUT_MS`
2. **凡结构皆可注入** —— 隔离标签是文本，命令输出也是文本，在同一层。`echo "</untrusted_context>"` 一行就越狱了。**回执里凡是「结构」，命令输出都能伪造**
3. **「后台」在 shell 里有四种实现，可杀性完全不同** —— 凭词感会把最无害的 `nohup` 当成最危险的
4. **防御措施自己成了故障源** —— 为防孤儿加的 watcher，第一时间踩了我们自己刚记录下来的坑
5. **防线要按「失败模式」分类，不是按「措施」分类** —— 三道防线看起来都在收拾进程，但问一句「Agent 是怎么死的」就会发现它们完全不能替代
6. **竞品的做法要连着前提一起抄** —— Gemini 的 `TERM=xterm-256color` 抄值不抄前提，就抄到了一个对我们有害的配置
7. **阈值不能压在样本簇上** —— `Wall time` 5 秒改 3 秒的实测过程：一个忽隐忽现的字段，比它恒写或恒不写都糟
8. **单出口约束的代价** —— `Promise<string>` 很干净，但它要求「一定要有出口」由我们自己保证。**好的约束不会自动成立，它需要被守卫**
9. **「一个问题该放哪一章」的判据是耦合度，不是工作量** —— 生命周期问题完全由「跳过」制造出来，**一个自己制造的问题，不能留给下一章**
10. **`ToolContext` 四次都没扩展** —— 「上下文对象」是最容易被滥用的结构，因为任何东西塞进去看着都合理
