# E02-S004：Backlog

> 范围外事项，不是已承诺的后续排期。

[Story](../README.md) | [总览](./00-overview.md)

## Backlog

| 事项 | 原因 |
|---|---|
| 模型 write_stdin / poll / yield / session | 本轮是人操作，模型续写需另立协议 |
| Windows/ConPTY | shell、信号和 native 生命周期须独立验证 |
| headless 自动回退 | 无法兑现人工接管，继承 stdin 可能误消费输入 |
| 交互后台化、detach、重连、多会话 | 需要所有权与界面焦点设计 |
| 录制、回放、分享正文 | 改变隐私边界，不能顺手接 OutputSink |
| 自动识别交互命令 | 命令名启发式不可靠，显式入口已满足需求 |
| 完整进程隔离 | PTY 和目录限制都不是沙箱 |
| 未观察到的重挂父进程／新进程组后代 | 不以轮询与组级回收冒充内核级 containment |

## 开放性问题

- 是否需要 idle/总时长预算？普通命令的跳过提示不是交互超时。
- 已有单批输入/待写输出保护，仍需对慢终端和全部 native 队列验证资源上界。
- 已恢复常用显示状态和 stty 属性；异常程序留下的鼠标及扩展键盘协议尚未穷尽。
- 外部 SIGHUP 已区分活端与不可用端；/dev/tty 探测遇到 EMFILE 等资源错误时仍保守跳过恢复，未把读探测扩张为所有终端 fd 健康检查。

## 本轮不采用的方案

| 方案 | 原因 |
|---|---|
| 模型持续决策作为主原理 | 不符 21:55 用户纠偏；旧材料保留为历史候选 |
| 默认 Yes 或 EOF 同意 | 缺少明确人工批准 |
| 仅 pause readline 就视为接管 | 原输入监听仍可能消费字节，必须完整隔离和恢复 |

## Deep Dive 话题池

- PTY 行规程：控制字节、EOF 与信号的区别。
- 人机输入权：如何显式移交而不产生竞态。
- 不采集正文的边界：参数、shell history 与录屏分别由谁负责。
