# E02-S001: 直接改动工作区（write_file + delete）- 总览

> Epic 2 第 1 个迭代：给 Agent 装上第一批写工具 `write_file` 和 `delete`，让它跨过「只读」边界，能创建 / 写入 / 删除工作区文件。

---

## 迭代目标

**核心目标**：让学习者理解「Agent 第一次拥有副作用（改变世界状态）时，最先要立住的是什么」——答案是**物理安全边界**，而非花哨的功能。

**定位**：Epic 2 的起点。在 Epic 1 只读工具体系之上，引入第一批带副作用的写工具，同时把「不越界」这条底线立起来。

**你将学到**：

- 带副作用的工具与只读工具在设计上的根本差异（安全边界、破坏性、幂等）
- 如何用最简单的方式守住「不写/删到工作区之外」这条物理底线
- 批量操作的「部分失败」语义该怎么设计，才对 Agent 友好
- 为什么「独立 delete 工具」是教学向选择，而非工业界主流

---

## 核心功能

### 1. write_file 工具

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `path` | string | 是 | 目标文件相对路径，基于 `ctx.cwd` 解析 |
| `content` | string | 是 | 文件的完整内容（全量写入） |

**语义**：不存在则创建、存在则覆盖，自动创建缺失的父目录（`mkdir -p`）。不做 append、不做 mode 开关。

**成功回执**（区分新建/覆盖）：

```text
已创建文件 src/config.ts（写入 128 字节）
已覆盖文件 src/config.ts（写入 156 字节）
```

### 2. delete 工具

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `paths` | string[] | 是 | 要删除的文件相对路径数组，逐个基于 `ctx.cwd` 解析 |

**语义**：只删文件、不递归删目录；对数组逐个「尽力删」，不因单个失败中断；最后逐条汇总。

**回执**（部分失败 = 方案 B）：

```text
已删除：a.txt, c.txt；失败：b.txt（文件不存在）
```

### 3. 物理安全边界

`write_file` 与 `delete` 执行前都校验目标路径落在 `ctx.cwd` 目录树内，越界（`..` 逃逸、绝对路径逃逸）一律硬拒绝：

```text
Error: src/../../etc/hosts 超出工作区，拒绝操作
```

---

## 设计原则

1. **安全优先于功能** — 带副作用的工具，第一件事是立住物理边界，而不是堆能力
2. **单一职责** — `write_file` 只做全量写、`delete` 只做删文件；局部改、递归删都是别的能力
3. **对 Agent 友好的回执** — 区分新建/覆盖、逐条汇总部分失败，让模型无需再读文件确认结果
4. **接口稳定** — 不为单个 Story 扩展 `ToolContext`，公共契约保持最小

---

## 技术选型

| 类别 | 选择 | 理由 |
|------|------|------|
| 写入实现 | `fs.writeFile` + `fs.mkdir({ recursive: true })` | Node 原生，零依赖；自动建父目录 |
| 新建/覆盖判定 | 写前 `fs.access` 探测文件是否已存在 | 决定回执用「创建」还是「覆盖」 |
| 删除实现 | `fs.rm`（非 recursive）| 只删文件；目标是目录则报错 |
| 路径边界 | `path.resolve` + 前缀判断（相对 `ctx.cwd`）| 简单、可预测的硬拒绝；不引入 permission 框架 |
| 返回契约 | `Promise<string>`，错误用 `Error:` 前缀 | 与 Epic 1 现有 4 个工具完全一致 |

> 明确**不做**：破坏性确认（留后续专章）、软链解析、危险路径黑名单、递归删目录、append/局部改（留 S002）。
