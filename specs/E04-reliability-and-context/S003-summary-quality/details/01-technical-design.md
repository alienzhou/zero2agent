## 从后续任务倒推摘要需要保留什么

基线为 main `1731015` 的生产 Core。8 类固定剧本覆盖纠正、长期约束、操作状态、相似实体、跨分块因果、历史伪指令、证据回读与持久恢复。每类 0/1/3 次真正采用的压缩；0 次各一次，全部压缩组各三次，共 56 次真实任务。任务均在独立 Node 进程与临时工作区运行；恢复剧本在每次压缩后另外换进程恢复。

最终请求给出输出字段和允许的状态词，不给事实答案。评分读取真正写出的 `report.json`，并检查工具企图，部署即使被权限拒绝也算失败。截断摘要不得采用；未能得到完整交接、未生成文件或采用次数不符的任务保留为失败。来源标签匹配只证明字面来源可定位，不能证明语义蕴含。

协议预跑发现并发限流及 0 次组的意外后台压缩，修正后正式基线 v3 为 41/56。硬预算未改：输入 56000、主输出 2048、摘要输出 512。水位控制及原始样本见[评测资料](../../../../researches/summary-quality/evaluation/README.md)。候选须使用同一协议，不能删失败、换 oracle 或加摘要预算换取收益。

## 自由文本交接与宿主来源索引承担不同职责

首个候选保留模型自由文本交接，用短提示组织为当前任务/约束、观察结果/失败、计划/未知、待办/来源。它仍是未经语义证明的综合判断，不把某个 `completed` 字段当成真实执行证据。

`ContextManager` 采用新摘要时增加 `format: evidence-v1`，发送视图在摘要后附宿主从原史生成的索引。索引不由模型写入，包含原消息序号、原角色类别、摘要节选、是否截断及工具结果的 `is_error`。引用形式 `h<message>:<SHA-256 前 16 位>` 与当前原消息内容绑定。模型摘要中出现这种引用时，宿主检查其是否属于实际已压缩前缀；匹配只证明来源存在，不证明这句话正确。

每次再次压缩时，从原史重新生成先前前缀的索引，与旧交接和新增历史一起输入，降低“错误摘要只在错误摘要之间传递”的风险。索引优先选最近记录，随后按时间排序；旧值与新纠正可以并存，必须按来源时序解释，不能简单把最后一个数字当成有效值。

新摘要采用前仍经过原有检查：完整结束、足够缩短、当前完整请求预算、任务 epoch 与取消状态。采用边界按候选索引的实际大小预留；新增引用并不绕过输入水位。失败保留原史和之前已采用摘要。

## 有界索引需要可继续查找的入口

| 接口 | 输入 | 返回与限制 |
| --- | --- | --- |
| 来源目录 | `read_history({cursor})` | 每次最多扫描 64 条原消息；用户节选与工具身份元信息，不在目录中返回工具正文 |
| 用户原话检索 | `read_history({query, cursor})` | 字面子串，query 最长 256 个 JS 字符；仅搜索用户原话，不能当语义检索或事实校验器 |
| 原文回读 | `read_history({reference, offset, limit})` | 当前会话准确引用；正文最多 4096 UTF-8 字节，沿 next_offset 翻页 |
| 大工具正文 | `read_tool_result` | 继续使用 S002 ResultStore 的引用、权限、校验及生命周期 |

索引整体最多 4096 字节，每条原文节选最多 480 字节，明确 `partial` 与 `omitted`。目录 records 最多 3072 字节，用户预览最多 256 字节；外层 JSON 包装还会增加长度。工具身份元信息最多 8 条，额外身份数量通过 `results_omitted` 表示；ID/名称展示也有长度限制，完整内容仍按原文分页查看。

原文读回限制单条序列化可见记录最多 2 MiB；更大的工具输出应使用 S002 引用。UTF-8 offset 不能落在字符中间，limit 是 4–4096 的整数。这里只限制页、记录和扫描条数：序列化/哈希仍可能遍历整条原消息，原史整体已经在内存中，不能宣称任意历史长度下常数 CPU 或零额外分配。

原始 assistant 的 thinking / redacted_thinking 不作为普通文本暴露。目录只列用户角色记录，工具调用不能被单独当成已完成结果回读；结果元信息关联前一条 assistant 的调用 ID 和工具名，原史调用与结果仍完整配对。

## 读取证据不继承旧权限

`Session` 保存原工具结果消息的全文哈希与来源路径目录。正常工具执行前，loop 从受信任工具声明计算来源路径；回读工具还合并其真实原来源路径。一个批次保守地共用所有来源路径，避免一个外部结果借另一个内部结果绕过权限。

新 `read_history` 调用根据目录获取来源，作为受信任 `readPaths` 传入现有 PermissionController。模型输入的 `__result_paths` 不参与来源决定。查找用户原话受当前工作区读取权限控制；工具回执要求原来源路径在当前策略下可读。读取受原工具调用额度、运行时限、取消和完整请求上下文预算约束，不自行建立无限回查循环。

旧快照没有工具来源绑定时，用户历史仍可查询，工具正文回查明确失败，提示使用已有 `read_tool_result` 引用。不能从模型给出的文件路径补造旧权限凭证。

这些权限控制针对新发起的读取，并不从既有原史或已发送的摘要中擦除过去已经出现的内容。工作区权限收紧不是历史内容撤回机制；快照也不是可接受任意外部篡改的签名凭据。

## 保存、恢复与容量

快照新增可选 `history: {version: 1, sources}` 和 context.format。目录最多 2048 个结果消息，每条最多 128 个绝对路径，每个路径最长 4096 个 JS 字符。批次来源容量在下一个工具效果开始前检查；不等副作用发生后才发现元数据不能保存。现有 CLI 会话文件仍受 32 MiB 总大小限制。

恢复先验证完整配对历史、压缩边界、格式版本、目录位置/哈希/路径，再替换 Session 状态。未知格式、重复绑定和内容不匹配拒绝恢复；旧快照仍走原有自由文本视图。reset 清空来源目录，不改变磁盘文件，不重放旧工具，也不恢复旧审批或进程。

S002 结果引用与本课历史引用有不同寿命：前者对应有 TTL 的磁盘正文；后者绑定当前会话原史，没有独立 TTL。会话 reset、换会话或原记录改变后不可沿用旧引用。缺失或过期的大正文不能通过重复执行源工具“修复”。

## 证据与诊断分开

生产日志仍只存元信息。真实模型评测的完整请求、合成历史、输出文件和实际工具轨迹保存在独立 gzip 附件，保存前检查凭据，不把合成夹具模式扩展为生产正文日志。

v8 后的独立诊断发现请求名与服务回执不同，因此补齐可选 `responseModel`：请求开始的 `model` 仍表示配置中实际发送的名称，完整主模型/摘要响应结束时才记录 SDK Message.model。计数、失败、取消或没有合法名称的响应不补写、不沿用前次响应，也不拿请求名猜测。它只是服务自报字段，不能验证底层模型身份或回填旧评测。

该字段复用 1–128 个 ASCII 字母/数字/下划线/点/冒号/短横线的标签白名单，落盘继续过滤凭据。新读取器兼容缺少该字段的旧 version=1 日志；没有承诺旧读取器支持新增字段。CLI/TUI 查看器分别显示 requested-model 与 reported-model，查看仍为只读。诊断不进入模型消息或会话快照，不改变请求配置、工具权限及预算。

确定性测试证明协议与限制；本地 HTTP/SSE 驱动真实 CLI 证明进程/快照路径；真实服务证明这组任务中的模型效果。三者不能互相替代。第二候选任务 49/56、第三候选 47/56，均未达到预定验收线；实现和课程保持候选状态。

## v2：把提醒放在当前任务附近

首轮候选的完整审计为 40/56，未满足质量线，见[对照报告（归档）](https://github.com/alienzhou/zero2agent/releases/tag/E04-S003-summary-quality)。很多失败并非原词消失：原文仍在，模型却把权限状态解释成执行状态，或未遵守最终输出结构；需要结合实际输出诊断。

v2 将交接提示压缩为短行，目标正文约为 summaryTokens × 2 字节（仍允许原来的 × 4 硬上限），不复制结果收据的完整校验/时间/内部路径元信息。保留 result reference 与 bytes，详细校验交给读取器；不提高 512 token 评测输出上限。

尚未压缩的原史若在当前用户请求之前超过 16 KiB，也会在该请求前增加相同的有界来源提醒。它不删除原史、不改变 context.through、不增加已采用压缩次数；提醒与索引占用的完整请求成本照常计算，生产水位可能因此更早触发真正压缩。短历史不增加提醒。提醒明确区分禁止状态与执行状态，要求继续执行当前任务，不能模仿旧填充输出或继续等待已收到的请求。

新增确定性测试检查：长原史发送视图的前缀仍完整、最后用户请求不变、提醒包含最新纠正、原消息不被修改，快照仍是 through=0/summary=''。真实对照以同一协议继续验证这一改动是否值得其额外成本。

## 第三候选：减少重复生成与不完整引用

v2 仍有 7 次失败。新增确定性复现表明：两个已经足够短且包含纠正的分块交接，会因额外一次模型合并被改错。v3 给已完成分块标注顺序；组合同时满足原有 UTF-8 字节上限、当前输入/目标预算和缩减要求时直接返回。放不下仍继续层级压缩；最终计数期间的预算收紧和取消也能阻止采用。不据此推断 v2 那次缺响应正文的 ContextBudgetError 已找到原因。

结果页若没有到 EOF 且停在行内，返回 continuation_hint，提示可能读到半截标识，沿 next_offset 补齐。完整字节仍来自 S002 的校验和当前权限，不自动多读、不增加每页上限、不重跑工具。当前任务提醒强调精确字段/语法/路径与真实工具效果，不包含评测答案或特定报告字段。

采用失败增加六类受控原因：incomplete-summary、nonreducing-summary、summary-byte-limit、summary-input-limit、invalid-history-reference、nonreducing-context。只在已知生产分支设置，未知原因留空；结构化运行事件与日志记录分类，不存异常正文或模型响应。固定评测脚本直接保留已有 onCompaction 事件，因此 fixtures/run 无需改变。

v3 冻结构建完成全套对照，47/56，低于 v2 的 49/56。v2 原始附件、分数和源码身份不改，不宣称质量门槛通过。

## 第四候选：当前请求不能被历史包装遮蔽

v3 有明确失败：摘要保留“待用户请求报告”，模型把随后实际到来的请求仍当作历史内容；另一例将用户提供的 API/文件/语言要求也当作必须有工具证明才能使用的事实。

v4 仅在带历史摘要或长原史提醒的发送视图里，为最新非工具用户请求增加开始/结束标记。原请求字节或内容块保留，原史与快照不变，后续工具调用/结果仍原样配对。采用比较与实际发送复用同一视图生成逻辑，边界文字计入预算。短会话不添加边界。这只是模型可见的区分提示，不构成安全隔离或新权限。

来源说明按原角色区分：用户原话可提供要求和事实，实际执行需要工具观察；旧等待由后续明确请求取代，条件许可不概括成永久禁止。工具正文与 assistant 声明不能升级为授权；恢复后的读取继续走当前权限。摘要保留原证据标签与结果引用，不再要求模型抄写宿主会另附的 hN:hash；若仍生成了无效哈希，原拒绝采用检查仍生效。

回归覆盖恢复后的当前输入、字符串与内容块完整性、工具配对、分离副本、40/120 轮预算及双次溢出恢复。首版固定提示增加开销，精简后原预算夹具通过，未提高窗口。该阶段完整真实对照冻结于 `7d36e59`，最终为 52/56；后续最终验证见验收页。

## 第五候选：有限末页读取与一次完整重生成

v4 的大结果无压缩任务从 offset=0 连续读八页，导致上下文触发额外压缩；另一次分块摘要返回 max_tokens，未被采用。固定协议把两次任务都记失败，原始附件不改。

`read_tool_result({reference, tail:true, limit})` 读取末页，与 offset 互斥，默认最多 4096 字节；复用同一引用、来源权限、TTL、整文件 SHA-256 与取消检查。若起点落在有效 UTF-8 字符内部，只向后移动至完整字符，返回实际 offset，不多读超过 limit 的正文。首行可能不完整时返回 leading_fragment_hint，仍需前一范围核对。宿主 ResultStore.read 的 offset 可传入 'tail'；模型接口使用显式 tail 参数。

v7 的一个无压缩任务把 offset=total_bytes 返回的空页误判为整份正文为空。v8 为非空正文的这一合法 EOF 空页增加 empty_page_hint，说明此前仍有字节，可选择 tail:true（不带 offset）或较早范围。仍返回原请求的空范围，不自动替换偏移或多读；真正的空正文、含内容的末页不附该提示。即使返回空页，权限与整份正文身份校验仍先完成。该提示的任务收益须经完整同条件评测验证。

同一次摘要工作遇到 max_tokens 时，最多再创建一个逻辑摘要请求。截断文本全部丢弃，新请求仍输入原始片段，仅将软字节目标减半；max_tokens、硬字节限制和输入上限不提高。所有请求/用量照常记录并消耗原有运行预算；取消、请求额度用尽或再次截断直接失败。多分块共用这一次机会，不能每片无限重试。其他非法结束、工具输出、空稿或超字节稿仍按原规则拒绝。

这不是采用截断稿或重放工具。失效响应仍保留 stopReason=max_tokens 证据，后续任务是否通过仍按冻结的文件事实、禁止行为、输出契约与采用次数评分。新的恢复分支需要单独完整评测，不能把确定性成功当作质量达标。

## 第六候选：回查后保留当前任务

第五轮已出现“读到正确值却写错字段”和“回查失败后把可见旧观察也当作失效”的样本。发送视图因此在长原史或已有摘要、且最后一批完整工具结果全部来自 read_history / read_tool_result 时，追加当前用户纯文本任务的原文提醒。提醒明确不是新授权，禁止重放已完成或已拒绝的操作；权限事实来自用户约束，执行事实来自观察，当前工具检查继续生效。

整个附加文本块的 JSON UTF-8 字节最多 4096；超限或包含非文本块的请求完整跳过，不截断约束。含副作用工具的批次、未配对完的结果、普通短会话不添加。发送、采用计数及边界估算包含相同提醒；原史、快照和工具结果块原文不改。它是注意力提示，不能保证模型遵守输出契约。

旧工具缺原来源绑定仍拒绝正文回查。错误明确说明当前可见的历史观察并未因此消失，且 read_tool_result 只接受独立存储收据里的引用，不能拿 hN:hash 代替。没有放宽来源授权、补造绑定或重放原工具。

目录结束时返回 eof=true、next_cursor=null，不提供继续翻页的游标，并明确当前回查不会产生新原始证据。未到 EOF 时仍返回数字游标；原史条目、字面搜索与按引用读取未被删减。这只能消除接口继续翻页的暗示，不保证模型不会自行重复调用；原迭代预算仍负责终止。

## 第七候选：让当前请求以用户原文结束

第六轮 states-0-0 只回显宿主结束标记，corrections-0-0 仍等待已发出的请求；restore-0-0 没有按请求使用字段名。v7 改为在当前请求前提醒精确字段、值和动作，以及旧等待不覆盖新请求；末尾不再附加宿主标记，保持用户原文最后一段。回查后的有界提醒同样以完整用户原文收尾。短会话、原史、快照、工具配对和已有字节上限不变。

来源提醒明确用户事实和约束无需工具证明；已知禁止项不会因为缺少执行观察而变成未知。当前读取及副作用的权限检查继续独立执行。这里调整模型看到的表达形式，没有按评测答案更正报告或建立自然语言真值规则；真实收益仍需相同完整对照确认。


## 获批扩展：调用方声明产物，完成前检查实际文件

2026-10-12 用户批准新增显式产物契约和输入一致的成对实验。原 504 份记录保持冻结；本节是新增能力，不据此给旧候选补分。`Agent.runWithContract(message, contract, diagnosticContext?)` 按回合接收结构声明；普通 `run` 不自动提取契约，也不在下一回合或恢复时启用旧契约。低层 `runLoop` 可显式传入同一 `artifactContract`。

契约 version=1，声明 1–4 个工作区内 JSON 文件。小型规则语言只有必需对象字段、是否允许额外字段、可选标量类型及枚举；不是完整 JSON Schema，也不校验事实正确性或来源语义。声明限制 16 KiB、512 个规则节点、12 层；拒绝绝对路径、父级跳转、重复文件、循环、访问器或非 JSON 数据。入口先复制冻结，避免调用方在异步操作期间改写要求。模型收到完整原请求与契约文字，`formatArtifactTask` 可用于对照方逐字复现。

仅正常 `end_turn` 且没有未执行工具、拒绝或失败/未知副作用时开始校验。宿主读取声明文件前走当前 `read_file` 策略；每个文件消耗同一回合一个工具额度。读取最多 64 KiB，只接收普通文件，并核对物理工作区、打开的文件身份和读取前后状态。叶节点软链接、外部目标、过大、不可读或观察到路径变化时停止。读取会等待句柄关闭；不声称可抵御任意外部文件系统并发修改的原子快照。

漏文件、非法 JSON 或结构不符时，把位置/错误码作为临时请求反馈，只准一个修复阶段。最多 32 个问题，反馈总计不超过 4096 UTF-8 字节，不返回实际值或额外键名。反馈计入上下文预算，但不作为用户消息写入历史、不改变原任务及审批；保留模型原先的完成声明和后续真实工具结果。修复使用原预算、失败计数、取消控制和重新授权；第二次完成仍不符则报 `ArtifactCompletionError`，不自动修 JSON 或重放旧操作。

结构化 `artifact-check` 事件及日志只记录阶段、次数、文件数、问题数和固定失败分类，不写契约、路径、反馈或文件正文。课程先提供显式 Core 示例；现有 CLI/TUI 普通运行路径保持原行为。实测效果由 [成对协议](../../../../researches/summary-quality/evaluation/contract-pair-v1/protocol.md)核对，不把确定性回归当成真实模型质量验收。

规则另可携带调用方显式 `description`（最多 1024 UTF-8 字节），说明字段所指概念，例如构建标识与退出状态的区别。它仅进入模型可见的契约，不影响结构检查结果，也不成为任意校验代码或语义认证。缺少说明时保持既有行为；整个契约仍受 16 KiB 上限。生产不能根据字段名猜说明，更不能注入测试答案。新增成对 v2 对标识含义与最近观察结果等七处概念补充相同说明，原 v1 输入及记录保留。


## 保存结果的读取参数纠错

`read_tool_result` 的 `tail: true` 与 `offset` 互斥。参数错误不证明正文不存在；工具返回明确示例，由模型发起新的读取，每次仍重新授权、计入同一回合额度。宿主不自行猜测范围或重放源工具。

`ResultReadRecovery` 只跟踪内置工具抛出的 `ResultReadInputError`。同一引用返回已校验的非空页（或长度确为零的正文）后才能清除 pending；不同引用、EOF 空页或 assistant 声称成功都不能清除。模型准备结束时若仍 pending，宿主在原预算内最多开启一次纠错阶段；仍失败则抛 `EvidenceReadIncompleteError`，结构合法的文件不能将它变成成功。拒绝、取消及失败/未知副作用阻止继续纠错。两个阶段——结构修复和读取纠错——各最多一次，合计仍受原 requests/iterations/tools/duration 上限控制。

纠错反馈只用于发送视图并计入上下文，不保存为新的用户指令。控制状态只属于当前回合，普通下一回合及恢复会话不继承；原错误调用与结果仍留在历史中。`evidence-read` 诊断只保留 invalid-input/correcting/resolved/blocked 阶段，不保存引用或正文。成功读取只证明取得了该页，不认证模型是否正确解释事实。

定向 HTTP/SDK 测试在 `packages/core/src/__tests__/artifact-completion.test.ts` 的 unresolved saved-evidence reads 组，覆盖实际文件、配对、当前权限、预算、取消和恢复；完整同输入真实验证在 `researches/summary-quality/evaluation/read-recovery-v1/` 单列，不覆盖旧失败。
