# 跨进程恢复协议

状态：实施协议，2026-10-16。基线为 `88ab5c4`。用户已授权实现、测试、文档与课程并提交 PR；2026-10-17 又明确授权最终复核通过后合并 PR #26。

## 发布边界

复用 SessionStore 的完整不可变 generation、文件 fsync 与独占发布，不建立第二份正文日志。一个 generation 同时包含原史、已采用摘要、结果目录、来源目录与可选 recovery 控制状态。仅最终已结算的整轮快照移除 pending；每个执行中 generation 都带原宿主 PID/host。最高版本损坏时明确失败，不回退旧版本。携带 recovery 时外层会话格式升级为 version=2，后续结算保持版本 2；新读取器兼容旧 version=1，旧读取器明确拒绝新版本，避免静默丢掉恢复控制。

等待完成的持久化接口依次发布：本轮输入 → 完整模型响应及工具列表 → 当前工具进入执行边界 → 该工具真实回执。执行标记在权限批准后、文件保护与实际工具调用前保存。执行边界内崩溃即视为效果未知，即使崩溃恰好发生在调用前。未记录执行标记的工具才能报告未执行。

只有完整模型响应进入记录。中断流仍是草稿。快照中的未结算调用使用明确标为宿主中断状态的错误配对占位，recovery 元数据区分未执行和未知；它不是工具返回的成功或失败证据。恢复后不执行这些调用。已结算工具保留实际结果，批次中其余调用分别标记，不整体重放。

持久化失败阻止启动后续工具和请求；已发生的效果不撤销。内存保留实际回执，错误必须可见。持久化在控制接口内等待，展示事件和诊断观察者不承担前置条件。

## 恢复与继续

复用 `--resume`、`--continue` 与 `/resume` 加载。旧进程仍活着或来自其他主机时仍保守拒绝。recovery 元数据持久存在，加载、保存、再次加载都不消除检查要求。恢复页面显示工具状态、旧运行身份、停止原因、预算计数的已记录范围与关联 checkpoint。

新增 `/recovery` 查看，`/recovery continue <指令>` 明确开启新一轮；单次/管道通过 `--resume UUID --resume-task <指令>`。沿用 `/recover UUID` 的文件 checkpoint 恢复语义，避免命令冲突。普通提问在待恢复状态下被阻止。新一轮使用当前模型、权限和预算，保留旧执行事实；不恢复旧审批、进程或自动调用旧工具。

S003 显式产物契约、未解决读取及已使用的修复机会保留在恢复控制状态。完成检查不能因重启获得额外纠错机会。旧预算不自动续接，必须由用户明确开始新一轮，界面明确说明。明确继续后，旧轮的拒绝/取消/效果状态继续作为历史证据；新轮的完成安全判断根据新调用重新建立，不继承旧批准，也不把旧轮风险标记永久当成不可恢复锁。无法兼容的控制状态拒绝恢复。

## 文件效果与容量

逐工具记录关联 session、operation、tool call，现有文件 checkpoint 已保存这些身份。查看入口提供对应 checkpoint 标识及现有差异/恢复命令；文件内容相同不能单独证明旧工具成功。未知 shell 或外部系统效果始终需要人工核对。

私有存储含对话与工具正文，沿用目录 0700、文件 0600、工作区隔离与 32 MiB 单份限制。执行快照增加写入频率，单会话新增 512 MiB / 2048 份版本门槛；超过门槛停止启动后续工作并保留恢复数据，本课不主动清理未结算记录；正文仍遵循 S002 独立生命周期，恢复引用不延长 TTL，缺失时明确失败。不宣称断电、网络卷或未测平台持久性。

## 验收

真实子进程在 response、tool-start、tool-settled 等边界终止；另在工具实际效果后、返回前终止。新进程读取磁盘并检查文件、调用次数、实际 SDK 请求和控制状态。覆盖部分批次、重复恢复、保存冲突、损坏/容量失败、权限改变、读取未解决与产物契约、旧进程活跃。工程测试、真实 PTY、真实模型分别记录；原始输出进入忽略目录，Git 只保存复现和精简结果。
