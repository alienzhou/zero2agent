# Epic 5：扩展能力

[首页](../../README.md) · [Roadmap](../../docs/roadmap/README.md) · [四课范围与验收](./course-plan.md)

让现有 Agent 读取项目约定、按需使用技能、调用外部工具，并执行可配置的检查。四种扩展分别回答“遵循什么规则”“怎样完成这类任务”“还能调用什么能力”“哪些步骤必须经过程序检查”。

状态：2026-10-17，S001 实现、完整回归和课程验收通过，按用户授权由 [PR #27](https://github.com/alienzhou/zero2agent/pull/27) 合入 main；S002–S004 保持规划状态。E04 已通过 PR #26 收束。

| Story | 课程主题 | 读者完成后的结果 | 状态 |
| --- | --- | --- | --- |
| [E05-S001](./S001-project-instructions/README.md) | 项目指令与 AGENTS.md | 能说明一项文件操作适用哪些项目规则，以及这些规则来自哪里 | 已合入 PR #27，网站未部署 |
| E05-S002 | Skills 的发现与按需加载 | Agent 先看技能目录，选中以后才读取步骤、参考资料和脚本 | 已规划 |
| E05-S003 | MCP 工具接入 | 配置一个本地服务，外部工具进入同一条审批、执行与结果读取链 | 已规划 |
| E05-S004 | Hooks 与扩展能力验收 | 用执行前后及完成前的检查收束任务，并跑通四种扩展的组合案例 | 已规划 |

依次实施 S001 → S002 → S003 → S004。使用同一个小型项目完成四次增量：遵循目录约定修复函数 → 通过修复技能补测试 → 从 MCP 查询固定工单资料 → 由 Hook 校验改动与最终报告。

每节课的新增范围、明确延期项、代码起点、故障场景和交付门槛见[详细课表](./course-plan.md)。实施某节时再创建对应 Story 的五篇 `details/`，不预先生成空白 Spec 或未实现的课程页面。

E05 完成后，当前五阶段主线的实现与教学内容可以收官。站点部署与图文发布单独跟踪；Agent Teams、Plan、Task List、Long Running 继续作为远期选题。
