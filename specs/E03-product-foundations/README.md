## 这个 Epic 做什么

让对话跨轮延续，让工具执行遵守授权，让使用者能看见运行状态、恢复会话、追查问题，并回退文件改动。课程计划已于 2026-10-01 确认；S001 已实现但未合入／发布，其余为待实现能力。

## 课程边界

- **先做最小会话。** S001 只做进程内历史和新对话入口；必须明确消息完整性、会话隔离，以及出错或中断后的历史处理。落盘恢复放在 S004，上下文压缩放在 Epic 4。
- **Approval 靠前讲。** S002 先用简单终端提示跑通授权，S003 再接入 TUI。复用并梳理已有工作目录校验，不能把路径校验或用户批准当作 shell 沙箱；E02-S004 的人工终端确认也不等于通用权限机制。
- **架构随交互需求改造。** 基于已有 Core 事件回调补齐状态与控制接口，不单开抽象重构课，也不在本阶段实现 Web UI。
- **恢复与回退各有边界。** S004 不恢复旧进程；S005 不把所有日志灌进模型上下文，也不改变人工终端正文不采集的约定；S006 的回退范围是文件，不是外部系统状态。

复杂异常恢复、长上下文与工具上下文管理留给 Epic 4；AGENTS、Skills、MCP、Hooks 留给 Epic 5。
