# 文件保护的技术设计

[课程](../README.md) | [总览](./00-overview.md)

## 可信捕获边界

Tool.checkpointPaths 是宿主注册元数据，不发给模型。Core 在授权与工作区检查成功后，解析指定输入字段中的路径，调用 AgentOptions.fileMutations，并传入 execute 闭包。闭包再次检查 AbortSignal。未配置 handler 的 SDK 用户维持原行为。

本课文件存储拒绝不支持的路径，不降级为无保护写入。严格路径规则意味着含目录、软硬链接或常见敏感文件的调用可能整次拒绝；默认关闭保护时旧工具自己的契约不改变。这是一条明确的保护策略，而不是操作系统沙箱。

## 对象与清单

按 realpath(cwd) 的 SHA-256 隔离工作区。存储由 objects/<sha256>、records/<UUID>.json 与短期 lock/ 构成。正文用 Gear 内容定义分块，16 KiB 后低 16 位为零切分，256 KiB 强制边界；SHA-256 寻址、deflateRaw level 3 编码。

FileVersion 保存 hash、size、mode 和有序 chunks；null 区分文件缺失。Checkpoint 保存 version、sequence、UUID、工作区哈希、创建时间、tool/restore、pending/ready、进程身份、关联调用和 changes。读取限制清单 1 MiB、块压缩体 257 KiB、解压 256 KiB；完整文件重建验证字节数和 SHA-256。

普通文件捕获校验每层祖先、O_NOFOLLOW、nlink=1、读取前后 stat、完整长度和内容哈希。单文件最多 32 MiB，读取以单文件缓冲为主；并非流式常量内存。恢复期间目标数据和校验缓冲可能同时存在，不声称内存只有一个块。

## 执行协议

1. 获取工作区存储锁，校验已存清单，清理过期的完成记录和无引用对象。
2. 存在 pending 时拒绝新受保护写入。捕获并发布所有 before，再发布 pending 清单。
3. 检查取消和文件当前值，确认未在保存期间改变，再运行真实工具。
4. 无论工具结果是成功、错误还是异常，都读取实际 after。无变化删除该记录；有变化发布 ready。
5. 结算失败保留磁盘上的 pending，明确告知副作用可能已发生；不自动重试工具。

对象和清单均写同目录临时文件、同步文件、rename 发布、同步父目录。GC 先删除过期清单并同步清单目录，再回收无引用块，避免先删除可达对象。未结算清单不会过期删除。

锁目录包含 PID、主机名和 nonce。旧 PID 明确 ESRCH 时，在原锁目录内独占 claim、重读身份后接管，不先删除可能被后继拥有的锁。PID 复用、远端主机、无 owner 或残留 claim 都保守拒绝；这类极短初始化窗口需要人工检查。网络文件系统语义和断电尚未实测。

## 预览与恢复

正常回退比较 after/live 的完整哈希、长度和权限；计划 token 绑定原清单、模式与 live。所有目标内容先验证；任一冲突则不开始写入。确认时重新计算计划，旧令牌失效。

恢复先保存新的 restore/pending 清单，before 为当前文件、after 为目标。因此恢复自身可继续，也可在完成后再次 undo。恢复未结算 tool 时，先把当前版本也保存到恢复清单，再移除旧 pending；新意图保留双方证据。

文件在同目录暂存，写入、chmod、fsync 后再重查 live。替换已有文件用 rename；恢复本来缺失的文件用 link 发布以防覆盖新创建的文件，随后删掉临时链接；删除文件先重验再 unlink。没有通用原子多文件事务。中断后 /recover 按每文件 from/to/live 判定继续、跳过或冲突。

这些重验无法消除任意外部写入者在最后比较与 rename/unlink 之间的竞争。宿主只阻止自身忙时回退与已登记的后台命令；其他进程需用户协调。也不恢复 ACL、属主、xattr、时间戳、目录树或进程。

## 成本预算与展示

默认保留最近 50 条完成记录且最长 30 天，pending 保留。单调用最多 128 路径、前像/后像各 64 MiB；实际对象分配字节预算 256 MiB，并预留两份 1 MiB 清单空间；最多 16,384 对象。扫描清单最多 1024 个入口，对象也有上限。预算并非目录 inode / 锁临时文件的精确文件系统配额。

相同块在文件间共享。清理发生在捕获/恢复时，也可显式触发；没有常驻定时器。/checkpoint-stats 报历史逻辑量、存储文件长度和按 stat.blocks 计算的分配字节（不含目录本身）。容量满不会自动删除保留期内所有历史来让任务继续。

文本差异采用公共前缀/后缀消除后的连续替换区间，非最小 LCS。二进制、非 UTF-8 或双方合计大于 128 KiB 只显示大小与哈希；单文件最多 300 行，整体约 96 KiB 展示门槛。展示截断不影响恢复字节。

## 会话与 UI

TUI 的列表、差异、回退预览独占焦点；显示前的 typeahead 不确认，括号粘贴被屏蔽，Enter 默认取消。支持方向键、Page、Home/End、Esc/Ctrl-C 返回，草稿保留。

Conversations.undo 在空闲状态先保存会话，执行文件恢复后追加一条已发生的文件恢复语义事实，再保存。原 tool_use/tool_result、摘要边界和日志不倒退；若末次会话保存失败，恢复已发生、内存事实保留，需 /save 重试。独立无密钥 CLI 不替别的会话写历史。

## 隐私

与 S005 元信息日志不同，Checkpoint 明确含文件内容。本地目录 0700、文件 0600；没有加密或签名。拒绝 .git/.hg/.svn/node_modules/.ssh、.env/.env.* 和 .pem/.key；其他路径仍可能含秘密，用户应按自己的存储策略管理并可显式关闭捕获。

恢复 pending tool 时会先发布新的 restore intent，再移除旧 pending。若在交接窗口中断，两条记录会暂时共存：继续恢复新 intent 时，只接受 sourceId 对应且所有路径、目标版本完整匹配的旧 tool pending，然后同步引用删除；其他 pending 仍阻止恢复。对应精确故障注入用例先复现阻塞，再验证安全续接与反向撤销。
