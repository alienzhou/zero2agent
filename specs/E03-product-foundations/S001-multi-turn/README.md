## 从“接着改”到“对话放不下”

第一轮让 Agent 分析测试，第二轮说“按刚才的建议补一个测试”：下一次请求必须带上先前的回答与工具证据。再连续读取几个大文件，即使只过两轮，请求也可能很长。反过来，很多轮短问答未必接近窗口，因此不能只按轮数压缩。

| 概念 | 生命周期 | 保存或执行什么 |
|---|---|---|
| Session | 从创建到清空／进程退出 | 原始历史、工作上下文与运行互斥 |
| Turn | 一次用户请求到完成／失败 | 新请求及本轮产生的消息 |
| Loop | Turn 内反复调用模型和工具 | 推理、工具调用、结果反馈 |

## 这个 Story 要做什么

同一 Agent 的多轮共享历史；发送请求前，再把历史组织成能放入窗口的工作上下文。**保留原始记录，不等于每次都向模型发送全部记录。**

- **做**：进程内会话、工具配对、失败证据、实例隔离、`/new`；请求预算、工具正文缩短、后台摘要、前台等候与压缩，以及手动 `/compact`。
- **不做**：会话落盘与恢复、分叉、完整 TUI、全局取消界面、摘要质量评分或复杂检索。高级质量评估与更复杂的上下文工程仍留给 Epic 4。

## 先分清历史与工作上下文

Session 持有原始历史，Agent 提供入口，Loop 执行当前轮。`getHistory()` 返回原始记录的深拷贝；`getContext()` 返回当前已采用摘要和未压缩尾部组成的消息视图，不含独立的 system/tools 字段，也不是下一次发送必然使用的最终请求。

失败时不能删除整轮：工具可能已经写过文件。完成的调用与结果留在历史中，未完成的流式片段不提交；压缩只改变发送视图，不回退文件，不重跑工具。`/new` 才清空会话，但也不会撤销文件、日志或后台命令。

## 请求发出前，逐级减少上下文

预算必须包括 system、工具 schema、消息与输出／安全预留，而不只是聊天正文。已知默认模型 `claude-sonnet-4-20250514` 使用 200000 窗口；未知模型必须显式配置 `contextWindow`，不能猜测。默认 `conservative` 按 UTF-8 字节和结构开销保守估算，并非精确 tokenizer；`provider` 计数失败时拒绝放行。

默认目标／后台／前台阈值分别是**输入预算**的 `0.45 / 0.65 / 0.85`：

1. 小请求直接发送；达到后台阈值先缩短大工具正文，完整结果保存到临时文件，可按行回读，原始历史不改。
2. 仍达到后台阈值且未达前台阈值时，对稳定历史前缀启动摘要，当前安全请求不必等待。
3. 达到前台阈值时，先等已有后台任务，必要时继续前台压缩；不能安全装下就报错，不发送超预算主请求。
4. 摘要采用前重新计数，并核对前缀及任务代次；后台期间新增的消息原样保留，过期结果不能污染新会话。

目标阈值是压缩方向，不是一定可达的保证。自动前台摘要失败但完整请求仍在硬预算内时，重新计数后仍可继续；超过硬预算则拒绝。最新用户输入、固定指令或工具定义本身过大时，必须拆分输入或减少固定内容。摘要请求自身也要分块计数、限制输出与重试；输出 token 上限和摘要字节目标分别约束，不能混为一谈。

## 自动处理之后，再给用户主动控制

交互 CLI 对去掉首尾空白后的精确 `/compact` 做本地分发，前台等待压缩完成；命令本身不是新一轮问题，但摘要会调用模型。`/compact extra` 与 `/compactish` 仍是普通输入。

SDK 使用 `await agent.compact()`，返回是否采用了压缩结果；`cancelCompaction()` 取消压缩，不是全局 Turn 中断。手动 compact 与 run/reset 共享 Session 互斥约束，不能同时改写会话；后台摘要则允许与安全的主请求重叠。
