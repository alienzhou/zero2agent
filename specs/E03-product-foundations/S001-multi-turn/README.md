## 模型不会自动记住上一轮

终端再次出现输入提示，只说明程序准备接收下一条消息。模型能否理解“按你刚才的建议修改”，取决于下一次请求是否带上之前的对话和工具证据。

| 概念 | 生命周期 | 保存或执行什么 |
|---|---|---|
| Session | 从创建到清空／进程退出 | 多轮历史与运行互斥 |
| Turn | 一次用户请求到完成／失败 | 新请求及本轮产生的消息 |
| Loop | Turn 内反复调用模型和工具 | 推理、工具调用、结果反馈 |

## 这个 Story 要做什么

让同一 Agent 实例的下一轮带上完整历史，支持 `/new` 开始新对话。工具调用、失败与返回值都是历史的一部分；不能只保存最终文本。

- **做**：进程内会话、最终回答入历史、工具配对、失败后的可继续状态、实例隔离与重置。
- **不做**：落盘、恢复、列表、压缩、会话分叉、完整 TUI、全局取消界面。

## 关键实现

### 让会话活得比一次请求更久

Session 持有历史，Agent 提供日常入口，Loop 只执行当前轮。独立 `runLoop()` 和静态 `Agent.run()` 默认仍是一次性调用，避免隐式全局记忆。

同一实例运行第二次时，模型收到的不是“第二条问题”，而是“第一条问题 → 完整回答与工具证据 → 第二条问题”。system prompt 仍在请求的独立字段中，不需要重复塞进历史。

### 保留事实，不伪造成功

失败时不能直接删除整轮：工具可能已经写过文件。保留完成的调用与结果，未完成的流式片段不加入历史；用标明来源的 Harness 说明结束本轮，再把异常交给宿主显示。截断的工具调用不执行，必须返回失败结果补齐配对。

### 运行中不能清空，读取历史不能改写

一轮尚未结束时，第二次 run 或 reset 都会被拒绝。否则模型正在使用的历史与宿主看到的会话会发生分叉。本课用明确拒绝代替队列；读取历史返回深拷贝，展示层也不能修改原始工具参数。

## 做完后的效果

第一轮让 Agent 分析测试组织，第二轮说“按刚才的建议补一个测试”，模型应收到第一轮的分析和工具结果。输入 `/new` 后再提问，请求不再包含旧历史。

`/new` 只清空对话，不回退文件，也不停止已经在运行的后台命令。

从[分步跟练](./follow-along.md)开始：先运行不依赖真实模型的测试，再手动体验自然语言两轮对话。测试证明上下文正确传输，不保证模型一定遵循上一轮建议。
