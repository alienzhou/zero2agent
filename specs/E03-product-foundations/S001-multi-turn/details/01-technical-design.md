# E03-S001：技术设计

[Story](../README.md) | [验收清单](./03-verification-checklist.md)

> 实现已完成，本文机制对应未改变的 `ea498a3` 生产代码；最终验收测试 `3829868` 已合入 `main`（`f883252`）并通过全量复跑。compact-loop 12/12 及 strict 类型检查通过，真实模型语义质量未验收。

## 整体结构

- `core/session.ts`：原始历史、轮次与手动压缩互斥、上下文管理器、会话预算与 reset。
- `core/agent.ts`：持有 Session，固定创建时 cwd，提供 run / reset / compact / getHistory / getContext / cancelCompaction。
- `core/context-budget.ts`：窗口配置、输入计数、输出与安全预留、分级阈值。
- `core/context-summary.ts`：无工具摘要请求，分块与层级归并、有限重试及完成性校验。
- `core/context-manager.ts`：大工具正文缩短、稳定前缀摘要、后台任务采用与发送前闸门。
- `core/loop.ts`：原始消息追加、工具配对，每次主请求前 prepare，上下文拒绝后的有限恢复。
- `tui/cli.ts`：同一实例连续输入，精确拦截 `/new` 与 `/compact`，展示压缩状态。

不新增依赖、不扩展 ToolContext、不改为 provider-neutral 消息类型。当前仍使用 Anthropic MessageParam。

## 历史与发送视图分开

Session 开始一轮时同步检查空闲、复制历史并追加 user 消息，在进入异步执行前设置 running。执行只操作本轮工作副本；结束时提交副本，finally 释放锁。`getHistory()` 深拷贝最后提交的原始历史，不受摘要和工具正文缩短影响。运行中读取历史不含当前未提交轮，空白消息拒绝且不改历史。

`getContext()` 返回当前采用的摘要、必要时单独保留的最新用户输入以及未压缩尾部的深拷贝；它不执行计数或主动采用刚完成的后台任务，也不包含 system/tools。真正的请求由 Loop 调用 prepare 后构造和计数。因此不要把这个检查接口当成已获预算许可的请求。

一个 Agent 对应一个会话和工作目录；静态 Agent.run 和未传 session 的 runLoop 仍是一次性，并在结束或失败时取消无后续所有者的后台摘要。持有实例或显式 Session 的宿主负责在退出时调用 cancelCompaction。reset 只在空闲时允许，同时取消压缩与在途计数、失效旧任务、清空历史与工作视图、恢复预算配置；不撤销文件，不删除日志或工具结果临时文件，不停止命令进程。新进程不会恢复会话。

## 预算不是按轮数截断

`ContextOptions` 接收 `contextWindow`、`maxInputTokens`、`maxOutputTokens`、`safetyTokens`、三个阈值比例、`summaryTokens`、`timeoutMs` 与 `counting`。仅精确模型名 `claude-sonnet-4-20250514` 有已知默认窗口 200000；任何其他名称都要求显式 contextWindow，包括兼容 API 的别名。

输入上限不得超过 `contextWindow - max(maxOutputTokens, summaryTokens) - safetyTokens`。默认主输出预留为 `min(4096, floor(window / 8))`，摘要输出为 `min(2048, floor(window / 16))`，安全预留为 `min(1024, floor(window / 32))`。无效整数、过小预算及阈值顺序错误直接拒绝，不静默放宽。

- `conservative`：序列化完整请求，计算 UTF-8 字节，再加消息、schema 与请求包络开销。覆盖 system、tools、messages、转义与工具结果；这只是保守估算，不是精确 token 数，也不能证明任意供应商的 tokenizer 上界。
- `provider`：调用 countTokens 计数，不把输出预留混成输入。失败、超时或取消时拒绝放行，不降级成不计数。
- 当前保守计数不支持 image/document；摘要分块边界也使用文本保守估算，因此本期只承诺文本及工具消息，不承诺切换 provider 就能完成多模态压缩。

默认 `target/background/foreground = 0.45/0.65/0.85`，分母为输入预算而非总窗口；要求 `0 < target < background < foreground < 1`。目标值用于选择前缀和判断继续压缩，不承诺每次都降到目标。不可压缩的最新输入加 system/tools 已超上限时，直接要求拆分输入、改用文件引用或减少固定指令。

## 自动处理：先缩短工具正文，再摘要

每次主模型请求前，包括同一 Turn 内工具返回后的下一次请求，都执行以下流程：

1. 尝试采用已完成的摘要，检查最新输入及固定开销，计算完整工作请求。
2. 达到后台阈值，先处理超大的字符串 tool_result：把全文写入受限权限的临时文件，仅在工作视图保留短预览、文件引用和按行回读提示。保留 tool_use_id，不重跑原工具；原始历史正文不改。
3. 重新计数。仍在后台与前台阈值之间，且没有在途任务时，为稳定前缀启动后台摘要；当前安全请求继续。
4. 达到前台阈值，等待已有后台摘要；采用后仍需缩减则继续前台摘要，有限尝试后重新计数。
5. 前台阈值不是硬拒绝线。固定提示占比高时，目标可能不可达；自动前台摘要失败但原请求仍在硬输入预算内，可重新计数后继续。超过硬预算必须拒绝，计数无法完成或操作已取消也不能放行。手动 compact 的失败仍返回调用者。

临时文件不是会话持久化或审计存储，可能被系统清理；reset 不保证删除它们。超长单行会在保留原 `.txt` 全文之外增加 `.chunks.jsonl`：每行记录零起始的 `start_character` 与 JSON 转义的 `text`，每片最多 128 个 Unicode 码点。用 read_file 按行读取切片文件可到达原文末尾；不能将码点偏移当作 UTF-8 字节偏移。回读应限定范围，避免把整份大结果重新装回请求。工具配对边界不可切断：不能在 tool_use 与对应 tool_result 之间截取前缀。

## 后台结果如何安全采用

每个任务保存代次 epoch、前缀截止位置 through、原始前缀快照及 AbortController。它只总结选中的稳定前缀；已有摘要可参与下一层归并。主循环在后台期间追加的新消息属于尾部，不会被旧摘要覆盖。

采用前检查任务已完成、代次一致、原始前缀未变；组合“新摘要 + 最新用户输入（如需）+ 当前尾部”，连同 system/tools 的完整请求重新计数，确认确实缩小。异步计数返回后再次检查代次与取消状态，然后替换工作视图；采用只是状态更新，发送前仍有硬预算检查，不能把“变短”当作“必然装得下”。取消、reset、前缀变化或无缩减结果都不能写回新会话。相同失败前缀不会在每次安全请求前无限重复启动后台任务。

手动 compact 与 run、reset 使用同一 Session 运行锁，先拿锁再创建压缩运行环境；运行中第二次操作明确拒绝而不是排队。自动后台任务允许与安全的主请求重叠，但一个管理器只维护一个摘要任务。前台需要它时等待而非同时再启动一份。`cancelCompaction()` 同时中止在途计数并让旧操作失效；异步边界检查代次，立即取消后不会继续启动下一次计数。它不是整个模型 Turn 的全局取消，也不回滚工具。

## 摘要请求本身也有上限

摘要器将历史作为引用数据，而不是执行指令，不提供 tools。要求保留最新意图与修正、约束、已完成操作及结果、文件引用、失败与未完成事项；摘要属于有损工作上下文，不是原始证据替代品。

过长源文本按 Unicode 码点切块，每块都在发送前计入摘要 system、引用包络和输出预留；多个块摘要再层级归并。当前实现限制模型调用、计数调用、层级深度、单块重试与超时时间，防止无限归并或付费循环。只有明确的输入过长错误才缩小块后重试；普通网络错误、空摘要、非文本、非 end_turn、输出截断、字节体积未减少至少约一成都不能被当作成功。

`summaryTokens` 是摘要请求的输出 token 上限，不是字节上限。另设 `summaryTokens * 4` UTF-8 字节的紧凑目标；这是独立大小约束，不是 tokenizer 换算公式。完成的文本还要按当前计数模式检查作为后续输入的预算，计数后读取最新收紧的上限；最后采用时再次检查包含 system/tools、摘要标记、保留输入及尾部的完整请求。

失败不删除原始历史，也不要求重放工具。后台失败时只要当前请求仍安全就可继续；自动前台失败也不能仅因超过软阈值就阻断仍在硬预算内的请求，但必须重新计数，硬超限仍抛错。手动失败向调用者报告。摘要在数据引用中仍可能包含不可信文本，提示词约束不是注入隔离的安全证明。

## 主模型拒绝上下文后的恢复

即使保守估算通过，供应商仍可能拒绝窗口。Loop 对识别为上下文溢出的错误最多恢复两次：收紧会话输入预算、前台压缩，再重建同一请求。恢复位于模型请求层，不回到工具执行层；已完成工具不会因为这次恢复再次执行。无法缩减或两次恢复耗尽就交给宿主报错，不无限重试。其他类型的异常不因此获得通用重试机制。

## 手动入口与 CLI 配置

`await agent.compact()` 返回是否采用了压缩结果，空历史为 false；操作失败抛错。交互 CLI 只将 trim 后的精确 `/compact` 分发为前台操作，等待结束后才提示下一次输入；命令不进入普通对话，但摘要请求仍可能产生费用。`/compact extra`、`/compactish` 是普通问题，单次命令行参数模式也不提供 slash-command 分发。

| 环境变量 | 含义 |
|---|---|
| `CONTEXT_WINDOW` | 当前模型总窗口；未知模型必填 |
| `MAX_INPUT_TOKENS` | 输入预算上限，不能侵占输出与安全预留 |
| `MAX_OUTPUT_TOKENS` | 主模型输出预留与请求 max_tokens |
| `CONTEXT_COUNTING` | `conservative`（默认）或 `provider`；CLI 当前仅精确 provider 启用供应商计数 |

SDK 通过 AgentOptions.context 配置，不自动读取上述四个 CLI 环境变量。CLI 通过 onCompaction 显示缩短、后台、等待、前台、完成与失败状态；展示通知不控制预算或任务成败。退出时取消压缩；已发生的请求费用不因取消退回。

## 消息配对与失败

| 路径 | 历史行为 | 调用者结果 |
|---|---|---|
| end_turn / stop_sequence / refusal | 保存完整 assistant 内容 | 返回文本 |
| tool_use | 保存 assistant 及逐个 tool_result，含失败标识 | 继续 Loop |
| max_tokens | 保留部分响应，工具不执行且补错误结果，添加截断说明 | 返回部分文本或说明 |
| 达到 20 次迭代 | 保留已完成工具结果，补上限说明 | 保持既有错误字符串返回 |
| 流式／网络异常、未知停止原因 | 不保存未完成流，保留完成前缀，补 Harness 中断说明 | 原异常抛给宿主 |

宿主说明不是模型输出：用 `[Harness]` 前缀，内容固定，不把原始异常（可能含请求细节）复制进历史。已经执行的文件副作用不回滚、不自动重试。

事件回调仅用于展示。同步异常和异步拒绝都被隔离，不等待异步回调；输入给观察者与工具分别深拷贝，不能反向改写历史。通知错误不能导致成功工具被标成失败，也不能使剩余调用缺回执。工具失败包括未知工具、抛 Error 或其他值，均产生对应 `is_error: true`；错误值的格式化自身也必须有无抛出兜底。

截断和迭代上限的 Harness 说明同时经 onText 通知宿主，避免只记录在历史、用户却看不到停止原因。

模型返回空 content 时也要向调用者返回并向展示层发送说明，避免只在历史里留下占位内容、用户却看到无声结束。

## CLI 退出

`exit` 关闭 readline 并完成已有后台清理逻辑后，释放非 TTY 输入管道。测试必须保持父进程的输入端打开，证明退出不是由 EOF 触发。TTY 不走管道销毁分支，保留终端交互与后台清理确认。

## 验证设计

单测捕获实际提交给 SDK 的请求快照，不只断言返回文本。多轮旧契约继续回归；新增测试分别覆盖完整请求预算、摘要自身分块预算、后台增量保留、等待与取消、手动互斥、工具正文文件回读，以及溢出恢复不重放工具。

E2E 使用本地 Anthropic HTTP/SSE 测试服务与真实 CLI 子进程，区分主请求流和无工具摘要请求。测试精确 `/compact`、失败续聊、`/new` 清理摘要及长对话请求预算，不用真实 Key，不向远端模型发送内容。最终验收测试候选 `3829868` 已通过全量复跑，生产代码仍为 `ea498a3`。强化用例实际执行连续两次恢复后让第三次上下文拒绝终止，断言副作用只发生一次；另一个用例组合成功／失败工具批次、后台摘要 pending、新工具对追加、模型失败与前台接管，检查证据保留。这里的实际恢复指运行本项目恢复逻辑，不是调用真实远端模型。版本化结果见[验收检查清单](./03-verification-checklist.md)。
