# E03-S001：技术设计

[Story](../README.md) | [决策](../../../../.discuss/2026-10-01/e03-s001-multi-turn/decisions/D01-session-contract.md)

## 整体结构

- `core/session.ts`：私有历史、深拷贝快照、轮次互斥、错误收尾与 reset。
- `core/agent.ts`：持有 Session，固定创建时 cwd，暴露 run / reset / getHistory。
- `core/loop.ts`：完整消息追加与工具配对；无 Session 参数时创建临时会话。
- `tui/cli.ts`：同一实例处理连续输入；拦截精确 `/new`，不把命令送给模型。

不新增依赖、不扩展 ToolContext、不改为 provider-neutral 消息类型。当前仍使用 Anthropic MessageParam。

## 历史所有权

Session 开始一轮时同步检查并设置 running，再复制历史并追加 user 消息。执行过程只操作本轮工作副本；结束时提交副本，finally 释放锁。快照返回深拷贝，运行中读取只看到上次已提交状态。空白用户消息拒绝且不改变历史。

一个 Agent 对应一个会话和工作目录。reset 只在 idle 允许，不重建工具、不删除日志、不清理后台进程。新进程不会读回历史。runLoop 默认一次性，显式 session 参数才复用。

## 消息配对与失败

| 路径 | 历史行为 | 调用者结果 |
|---|---|---|
| end_turn / stop_sequence / refusal | 保存完整 assistant 内容 | 返回文本 |
| tool_use | 保存 assistant 及逐个 tool_result，含失败标识 | 继续 Loop |
| max_tokens | 保留部分响应，工具不执行且补错误结果，添加截断说明 | 返回部分文本或说明 |
| 达到 20 次迭代 | 保留已完成工具结果，补上限说明 | 保持既有错误字符串返回 |
| 流式／网络异常、未知停止原因 | 不保存未完成流，保留完成前缀，补 Harness 中断说明 | 原异常抛给宿主 |

宿主说明不是模型输出：用 `[Harness]` 前缀，内容固定，不把原始异常（可能含请求细节）复制进历史。已经执行的文件副作用不回滚、不自动重试。

事件回调仅用于展示。同步异常和异步拒绝都被隔离，不等待异步回调；输入给观察者与工具分别深拷贝，不能反向改写历史。通知错误不能导致成功工具被标成失败，也不能使剩余调用缺回执。工具失败包括未知工具、抛 Error 或其他值，均产生对应 `is_error: true`；错误值的格式化自身也必须有无抛出兜底。

截断和迭代上限的 Harness 说明同时经 onText 通知宿主，避免只记录在历史、用户却看不到停止原因。

## 验证设计

单测捕获实际提交给 SDK 的请求快照，不只断言返回文本。覆盖多轮工具链、深拷贝、实例隔离、互斥、重置、错误恢复、截断调用及轮次上限。

E2E 使用本地 Anthropic SSE 测试服务与真实 CLI 子进程，逐次等提示符后输入，验证第二轮请求与 `/new` 后请求。不使用真实 Key，不向远端模型发送内容；这验证上下文传输，不声称验证模型语义能力。
