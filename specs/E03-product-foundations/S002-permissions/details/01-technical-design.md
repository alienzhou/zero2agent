# 执行前判断权限，宿主负责回答

## 决策顺序

工具 effect 由宿主注册：read、write、execute；缺省 unknown，不能仅靠工具名称识别。可选 paths 声明参数里的路径字段。默认模式允许工作区读；写、执行、unknown 询问；外部读询问。read-only 硬拒绝非 read 和外部 read；accept-edits 自动允许工作区写；bypass 跳过默认询问，但不能覆盖显式 deny / ask 和工作区写边界。

显式规则只支持工具全名（或 *）和顶层标量参数精确匹配。优先级 deny > ask > allow。同级不依赖位置；规则是宿主输入，构造时校验并复制。无模式和规则热更新，不从模型或项目文件读取权限配置。

## 路径判断

以 realpath(cwd) 为根；目标不存在时逐级找到已有祖先并解析软链，再拼接未创建尾部。工作区写不能指向根目录或根外。审批前与执行前均检查；写工具自身也保留路径检查，直接调用写工具仍有效。批量 delete 经通用闸门遇任一越界拒绝整次调用；直接工具的逐项尽力语义保留。路径校验不能阻止恶意并发替换、硬链接、shell 的外部副作用，不宣称是操作系统沙箱。

## 审批生命周期

Controller 属于 Agent。请求包含随机 request ID、模型 toolCallId、工具名、参数副本、cwd、原因及 AbortSignal。审批是等待的控制函数，与不等待的展示事件分开。响应必须是相同 requestId 的 allow 或 deny，只生效一次。没有处理器、异常、非法响应、超时和取消都拒绝；默认最长 120 秒，结束 abort 并清理计时器与挂起项。取消只取消正在等待的审批，不回滚已执行工具或中止整个 Turn。

参数与 cwd 不可被事件、处理器或调用方改写。Loop 先保存 tool_use，再依次授权和执行；拒绝生成同 id 的 is_error tool_result，批量调用继续配对。onToolStart 只在获批、再次校验后触发。所有展示 observer 的异常不能改变控制结果。

## CLI

环境变量 PERMISSION_MODE 和可选 PERMISSION_RULES（JSON 数组）在构造时校验。交互模式复用 readline；只有 stdin/stdout 都是 TTY 才能回答 Approval，y 表示批准这次，n/空白拒绝。显示 JSON 编码参数以消除控制字符，长参数保持完整；无“始终允许”选项。一次性任务也可在 TTY 使用独立 readline。管道与无 UI 环境 ask 直接拒绝；EOF、Ctrl+C 与超时终结当前询问，不当成同意。用户主动 /terminal 与 --terminal 仍走已有人工终端交接；模型提出 terminal 必先经过通用闸门。

## 测试与课程

规则测试、请求关联与等待取消；真实文件/软链接；Loop 下一请求证据；CLI + 本地 HTTP/SSE + PTY，证明代码分支真的到达。旧课程契约需明确选择原自动执行模式，不用隐式默认维持旧写行为。课程从“帮我修好，是否也能执行命令”开始，按情景→三态→竞品差异→实现→边界→验证→跟练组织。
