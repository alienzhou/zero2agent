# 批准与隔离，各自限制什么

[课程](../README.md) | [Backlog](../details/04-backlog.md) | [竞品依据](../../../../researches/permissions/README.md)

## 同一句命令有两种问题

“是否允许执行这次 command”是授权问题；“这个进程实际上能访问哪些文件和网络”是执行边界问题。终端命令获批后仍以宿主用户权限运行，`cwd` 只决定起始目录，不阻止命令使用绝对路径。文件工具里的路径校验也不能给 shell 建立隔离。

Codex 的官方配置将 approval_policy 与 sandbox_mode 分开；Claude Code 的权限规则由宿主执行。两者都说明判断用户意图与约束实际资源不是同一层。原始链接与版本核对在竞品研究中，不把本课的简化模式冒充竞品的全实现。

## 从一次批准扩大范围时，新增了什么判断

批准当前调用已经有完整参数、cwd、请求 ID；“同工具以后都允许”则需要回答：允许哪些路径、哪些命令、是否包括新参数、持续到本轮还是本会话、是否落盘，以及配置变化怎样撤销。把所有 terminal 调用统一缓存为允许，会把一次本地检查扩大为另一条完全不同的命令。

本课只实现一次批准。宿主可以明确配置精确规则，但 UI 不自动保存宽规则。长期授权还需可信配置来源与作用域，留给后续设计。read-only 的硬约束和 workspace 写边界不依赖用户回答，批准不把硬拒绝改成允许。

## 重查路径仍有界限

审批可能等待两分钟，这段时间目录可被替换为软链接。审批前检查不足，所以执行前重查、写工具再查。目标不存在时仍要解析已有祖先，避免新文件绕过软链接检查。

重查不能完全消除检查与打开文件之间的竞态，也不能识别硬链接的来源；不可信并发进程可以在间隙改写路径。需要更强保证时，应使用操作系统沙箱、受控文件描述符或专门执行容器，而不是宣称多加一次 realpath 就安全了。
