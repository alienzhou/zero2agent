## 1. 明确方案，并把核心原理放到前面

这次最终做的是：

> 人工确认 → Agent 暂停接收输入 → 人通过 PTY 操作 bash → 清理进程、恢复终端 → 回到 Agent。

参考了三类已有实现：

- **Aider**：人工直接操作 PTY。
- **pi**：暂停、恢复 TUI，结束后返回摘要。
- **Gemini CLI**：按键转发、窗口尺寸同步和 PTY 生命周期。

保留默认非交互命令执行，新增显式人工模式。**没有实现模型自行多轮填写 stdin，也不会自动把已经卡住的普通命令转换成人工会话。**

## 3. 终端接管与恢复已实现

主要代码在 [human-terminal.ts](../../../packages/tui/src/human-terminal.ts)。

具体包含：

- **启动确认**：展示命令、工作目录，默认拒绝；只有 `y/yes` 加回车才启动。
- **真实终端检查**：stdin、stdout 必须都是 TTY，不满足时拒绝，不偷偷降级执行。
- **PTY 桥接**：转发人的按键和程序输出，支持多轮输入、中文、行编辑及窗口尺寸变化。
- **输入独占**：接管期间隔离 Agent 的 readline 监听，避免同一按键同时进入 bash 和 Agent。
- **现场恢复**：保存并恢复 raw mode、输入流状态、监听器和完整终端设备属性。
- **收尾隔离**：程序退出到 Agent 恢复之间，继续丢弃私人输入，避免晚到按键进入聊天历史。

控制键也区分了职责：

- `Ctrl-C`、`Ctrl-D` 交给子程序，具体效果由程序决定。
- `Ctrl-]` 由宿主处理，结束整个接管。
- 默认交互 bash 中输入 `exit`，正常返回。

## 4. 退出、异常和隐私边界已处理

进程管理在 [human-terminal-process.ts](../../../packages/tui/src/human-terminal-process.ts)。

已处理的情况包括：

- 正常退出后清理仍存活的受管后台进程。
- 用户中止时清理原进程组与已观察到的后代。
- 进程扫描失败时仍执行组级清理，并报告错误。
- 外部 SIGINT／SIGTERM，以及真实终端断连。
- PTY 启动失败后的终端恢复。
- 信号退出不能被附带的 `exitCode=0` 误报为成功。

隐私上做了明确分流：

- 人工按键、终端正文不进入模型回执、普通输出收集器或应用输出日志。
- 模型只收到状态、退出码、信号等摘要。
- 宿主异常不原样透传，避免异常文本带出交互内容。

但这**不是无痕终端或沙箱**：启动命令可能已在上下文中，外部程序仍可能写日志、文件或历史。
